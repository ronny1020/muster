# Muster

[English](README.md) · [繁體中文](README.zh-TW.md) · [简体中文](README.zh-CN.md) · **日本語**

**AI エージェント CLI のために作られたターミナルです。**

`claude`、`codex`、`agy` は、普段お使いのターミナルとまったく同じように動きます。本物の PTY、完全な TUI、色、キーボード操作まで、すべてそのままです。Muster が加えるのは、ターミナルには知りようのない部分です。そのタブでどのエージェントが動いているのか、再開する価値のある会話があるのか、いつ止まってあなたの応答を待っているのか、そして別のタブを読んでいる間に作業ツリーに何をしたのか。

タブそのものが目的ではありません。Windows Terminal や PowerShell には何年も前からタブがあります。重要なのは、Muster がタブの _中身_ を知っていることです。

- 🎯 **ランチャーはまずどのエージェントを使うかを尋ね**、次に「新しいセッション」「続行」「再開」を提示します。失敗するものはグレーアウトされます。CLI に `No conversation found to continue` と表示させる前に、そのディレクトリに記録された会話があるかを先に確認するからです。エージェント自身の保存領域を読み取れる場合（現時点では Claude Code）、「再開」は会話をその画面に一覧表示し、それぞれを最初に尋ねた内容の下に並べます。CLI 自身のピッカーの中で手間をかける代わりに、クリック一つで選べます。
- 🧹 **エージェントのセッションマーカーはすべてのタブから取り除かれる**ため、別のエージェントの中から起動したエージェントも自分のトランスクリプトを記録します。これがないと、後で `--continue` しても何も見つかりません。
- 🐚 **セッションはログインシェル経由で実行される**ため、mise、nvm、`~/.local/bin` など、ご自身のプロファイルでインストールした CLI も見つかります。そうでなければ GUI アプリは最小限の `PATH` しか引き継がず、それらはどれも存在しないことになります。macOS、Linux、WSL でエージェントを終了すると、他のターミナルで終了したときと同じく、タブは同じディレクトリでそのシェルを渡してくれます。エージェントの出力は「スクロールバック」タブとしてプロンプトの上に残ったままです。その後タブはシェルのタブとして振る舞います。「クリック」/「スクロールバック」の切り替えと ⟳ はセッションを終了させてしまうため消え、**シェル統合** がオンならシェルのタブと同じコピー操作と補完が使えるようになります。Windows PowerShell では、タブはエージェントとともに終了します。
- 🟠 **各タブのドットはエージェントが作業中かどうかを示します**。セッションがまだ出力している間は脈動し、静かになってあなたを待っている状態になると点灯したままになります。出力そのものを読んでいるので、どのエージェントでも、通常のシェルでも機能します。
- 🔔 **エージェントが終わるとタブにドットが表示され、デスクトップ通知も届きます**。通知はターンの終了が告知される場合に限ります（Claude Code では、ご自身でインストールするプラグインによって告知されます）。複数のエージェントを走らせる理由は、今まさにそのエージェントを見ていないことにあるからです。
- 🌿 **フッターはエージェントが変えるディレクトリとその git の状態に追従し**、ドロワーからはタブを離れずにブランチを切り替えられます。
- 🔍 **エージェントが変更したばかりのファイルをクリックすると、その差分がターミナルの横に開きます**。シンタックスハイライト付きで、隣にはファイルツリーもあります。エージェントが何をしたかをレビューすることは、エージェントを走らせることのもう半分です。
- 🖱️ **出力内のパス、URL、画像はクリックできます。** エージェントの出力はそれらであふれていますし、タブにファイルをドロップするとそのパスが入力されます。

_To muster:_ 軍勢を集め、それを見渡すこと。ランチャーがエージェントを集め、ステータスバーと履歴ドロワーが見渡す役を担います。

macOS、Windows、Linux で動作します。Windows ではタブを WSL 内で実行することもできます。

## 📦 インストール

macOS と Linux では、ダウンロードしたものがアプリのすべてです。Windows では、マシンに Microsoft の WebView2 ランタイムがまだなければ、インストーラーがそれを取得します。

Muster は自動アップデートしません。アップデーターを持たず、外部に何も送信しません。これが後述の「プライバシー」の節で約束していることのもう半分です。

### 🍎 macOS

#### インストール

```bash
brew install --cask ronny1020/tap/muster && xattr -cr /Applications/Muster.app
```

1 行のまま実行してください。tap を追加し、アプリをインストールし、そのままでは macOS がアプリを開けなくなる quarantine 属性を消去します。その後、アプリケーションフォルダーから Muster を起動します。

または [Releases ページ](https://github.com/ronny1020/muster/releases) から `.dmg` を入手し、アプリケーションフォルダーにドラッグしてから、同じく `xattr -cr /Applications/Muster.app` を実行するか、初回だけ右クリック → _開く_ を選んでください。

#### アップデート

```bash
brew update && brew upgrade --cask muster && xattr -cr /Applications/Muster.app
```

tap を更新するのは `brew update` です。これがないと Homebrew は最後に見たバージョンと比較し、何もすることがないと報告します。`xattr -cr` が再び必要なのはインストール時と同じ理由で、アップグレードによって quarantine 付きの新しいコピーが置かれるからです。

**その後 macOS がフォルダーへのアクセス許可を再び求めますが、これは想定どおりです。** アプリはアドホック署名なので、macOS はバイナリのハッシュでアプリを識別し、リリースごとに見たことのないソフトウェアとして扱います。許可は引き継がれません。確認ダイアログを閉じてしまった場合は [フォルダーを読み取れないとき](#-フォルダーを読み取れないとき) を参照してください。回答は記憶されるので、アプリが二度尋ねることはできません。

新しいバージョンがあるはずなのに、アップグレードが最新バージョンはインストール済みと報告する場合、その意味は [問題が起きたとき](#-問題が起きたとき) に書かれています。

#### アンインストール

```bash
brew uninstall --cask ronny1020/tap/muster
```

アプリをゴミ箱にドラッグすると Homebrew の記録が残り、実際にはインストールされていないのにインストール済みと報告されるようになります。

### 🪟 Windows

#### インストール

```powershell
scoop bucket add ronny1020 https://github.com/ronny1020/scoop-bucket
scoop install muster
```

または [Releases ページ](https://github.com/ronny1020/muster/releases) から `_x64-setup.exe` を実行します。SmartScreen は認識されないアプリだと警告するので、**詳細情報 → 実行** を選んでください。現在のユーザー向けにインストールされるため、管理者権限の確認は出ません。

#### アップデート

```powershell
scoop update
scoop update muster
```

`scoop update` 単体では bucket を更新するだけです。アプリを更新するのは 2 行目です。

#### アンインストール

```powershell
scoop uninstall muster
```

`.exe` でインストールした場合は、代わりに **設定 → アプリ** から削除します。

すべて [Releases ページ](https://github.com/ronny1020/muster/releases) から入手できます。

### ⚠️ 警告が出る理由

このプロジェクトはコード署名証明書を購入していません。Apple Developer のメンバーシップも Windows の証明書も相応の費用がかかり、それを正当化できるだけのユーザーがまだいないからです。そのため macOS からはアドホック署名だけのアプリに、Windows からは署名のないインストーラーに見え、どちらもそう警告します。

macOS でインストールコマンドが `xattr -cr` で終わるのもそのためです。Homebrew はインストールするすべての cask に quarantine を付け、Gatekeeper は公証されていない quarantine 付きのコピーを開くことを拒否します。この手順を省略するための `--no-quarantine` フラグは Homebrew 6 で削除されました。

署名の代わりに提供しているもの：すべてのバイナリは、それが名乗るタグから GitHub Actions によって公開の場でビルドされており、そのワークフローは誰でも読めます（[`.github/workflows/release.yml`](.github/workflows/release.yml)）。Homebrew と Scoop の経路では、さらにマニフェストに記録されたチェックサムを検証します。

### 🕶️ プライバシー

Muster が自ら行うネットワークリクエストは 1 種類だけです。Web リンクにポインターを重ねると、ホバープレビューのためにそのページと、そこで指定された画像を取得します。対象はリンクが指すあらゆるアドレスで、`localhost` も含みます。Stack Exchange の質問の場合は代わりに `api.stackexchange.com` に問い合わせ、そのサイトのアイコンは `cdn.sstatic.net` から取得します。クリックしたリンクはブラウザーで開かれ、リクエストはブラウザーが行います。テレメトリー、アップデートの確認、アカウントは一切ありません。ファイルシステムと git の状態を読み取り、指定された CLI をローカルで実行するだけです。それらの CLI は、普段のターミナルとまったく同じように、それぞれの条件でそれぞれのプロバイダーと通信します。ドロワーの **プル** と **プッシュ** は、押したときにだけ、あなた自身の `git` をあなた自身のリモートに対して実行します。

エージェント CLI は別物で、Muster は意図的にそれらを同梱していません。お使いのもの（`claude`、`codex`、`agy`）をインストールし、まずはご自身のターミナルでそれぞれが動くことを確認してください。Muster はシェルとまったく同じ方法でそれらを見つけます。

ソースからビルドする場合は数個のコマンドで済み、Bun と Rust のツールチェーンが必要です。[CONTRIBUTING.md](CONTRIBUTING.md) を参照してください。

## 🚀 使い方

新しいタブはスタート画面で開きます。**フォルダー**（最近使ったものはクリック一つで選べ、参照して選ぶこともできます）と **エージェント**（9 種類あるので、入力して一覧を絞り込めます）を選び、セッションの開き方を選びます。シェルはその中に含まれていません。シェルのボタンはエージェント一覧とモードの間にあります。Claude Code ではそこで **ターミナルモード**（「スクロールバック」または「クリック」）も選べ、設定で既定に指定したほうが最初に選ばれています。モードを選ぶと、ターミナルがタブを引き継ぎます。

| エージェント | コマンド        | 新規セッション | 続行       | 過去から選ぶ        |
| ------------ | --------------- | -------------- | ---------- | ------------------- |
| Claude Code  | `claude`        | ✓              | 最新       | Muster 内に一覧表示 |
| Codex        | `codex`         | ✓              | 最新       | 独自のピッカー      |
| OpenCode     | `opencode`      | ✓              | 最新       | —                   |
| Gemini CLI   | `gemini`        | ✓              | —          | —                   |
| Goose        | `goose session` | ✓              | 最新       | —                   |
| OpenClaw     | `openclaw`      | ✓              | —          | —                   |
| Hermes       | `hermes`        | ✓              | —          | —                   |
| Aider        | `aider`         | ✓              | —          | —                   |
| Antigravity  | `agy`           | ✓              | 直前の会話 | TUI 内の `/resume`  |

このうち 2 つのコマンド名は無関係なツールと共有されています。`goose` はデータベースマイグレーション用の CLI でもあり、`hermes` は React Native の JavaScript エンジンでもあります。Muster は `PATH` で最初に見つかったものを実行するので、タブで違うプログラムが起動した場合はそれが理由です。

「続行」の列のダッシュは、その CLI がそのためのフラグを文書化していないことを意味し、Muster が忘れたわけではありません。CLI が持たないフラグを渡すと起動を拒否されるので、推測で埋めるのではなく、そのモードを外しています。それらの多くはいずれにせよ独自の履歴を保持していて、起動時にそれを引き継ぎます。

**再開** は、ターミナルの中ではなくここで一覧を開きます。各行はそのディレクトリでの過去の会話で、新しい順に並び、その会話で最初に入力した内容の下に表示されます。1 つクリックすると、エージェントがその会話に直接入った状態で起動します。新しいものから 30 件が表示され、それより多いディレクトリでは最後の行から CLI 自身のピッカーを開けます。残りはそこにあります。これはエージェント自身の保存領域を読むので、現時点では Claude Code のみが対象で、履歴のないディレクトリでモードがグレーアウトされるのも Claude Code だけです。Codex はこれまでどおりセッション内で独自のピッカーを開きます。上の表で「再開」の列がないエージェントには、開くべきピッカーがありません。

**代わりに通常のシェルを開く** は、同じウィンドウで普通のターミナルを使いたいときのためのものです。フラグは受け付けません。渡す先のプログラムがないからで、それがエージェント一覧の中ではなく横にある理由です。

**まだ存在しないディレクトリ** もエラーにはなりません。Muster は親ディレクトリも含めて作成することを提案し、確認するとそこでセッションを開始します。`~` はホームを意味するので、`~/code/new-thing` は期待どおりの場所に作られます。

**追加フラグ** は、それ以外のもの（たとえば `--model opus`）をそのまま渡します。引用符で囲んだ値は 1 つのまとまりとして扱われます。

**別のタブを見ている間も、タブは動き続けます。** 何も再起動せず、スクロールバックも失われないので、エージェントに作業を任せて後で戻ってくるのが通常の使い方です。

**タブがタイトルバーです。** macOS ではシステムのタイトルバーの中、信号機ボタンの後ろにタブが並びます。Windows にはシステムのタイトルバーがまったくなく、最小化、最大化、閉じるボタンはタブ列の右端に描画されます。そのため、ウィンドウの枠は 2 段重ねではなく 1 行で済みます。タブ列をドラッグするとウィンドウが移動し、ダブルクリックすると最大化します。タイトルバーとして当然の挙動です。Linux ではデスクトップ自身の装飾がタブ列の上に残ります。

## 📊 ステータスバー

各タブの下端に並ぶもの：

- **ディレクトリ**。`~` で短縮されます。クリックするとファイルツリーが開きます。ツリーの名前を示しているので、ツリーを開くのです。
- **ブランチ**。ブランチがない場合は `デタッチ @ 1a2b3c4` と表示されます。クリックすると履歴ドロワーが開きます。
- **`↑2 ↓1`**：まだプッシュしていないコミットと、プル待ちのコミットです。クリックすると、コミットのある場所である履歴ドロワーが開きます。
- **`+3 ~5 ?2 !1`**：ステージ済み、変更、未追跡、競合のファイル数で、1 つのボタンになっています。クリックすると、それらのファイルがあるレビュードロワーの「変更」ビューが開きます。変更のないツリーでは `変更なし` とだけ表示され、どこにも移動しません。
- **`src/auth.ts は…でも変更中`**：別のタブが同時に変更しているファイルです。「2 つのタブが同じファイルに触れたとき」を参照してください。
- **クリック / スクロールバック**：2 つのボタンで、タブ自身のモードが押された状態になっています。もう一方を押すと切り替わります。「自分の質問に戻る」を参照してください。
- **「過去のセッション」ボタン**：このディレクトリで記録された会話と、そこへ戻る手段です。「過去のセッション」を参照してください。
- **… で開く**：現在のディレクトリをエディターで開きます。VS Code（Insiders を含む）、Cursor、Antigravity IDE、Windsurf、Zed、Sublime Text、JetBrains の各 IDE、VSCodium、Neovim、Vim のうちお持ちのものを見つけ、どれを使うかは設定で選べます。macOS では、シェルコマンドがなくてもインストール済みのエディターが見つかります。VS Code の `code` は、コマンドパレットから「Shell Command: Install 'code' command」を実行した場合にしか存在せず、ほとんどの人は実行したことがないからです。
- **歯車** は右端にあり、設定を開きます。バーはまだ何も起動していないタブも含め、すべてのタブにあるので、歯車も常にあります。

これらはいずれも、何かを切り替えるのではなく、表示する対象の名前を示しています。ツリーがすでに開いている状態でディレクトリをクリックするとドロワーが閉じますが、変更数をクリックすると「変更」に切り替わります。ドロワーは最後に開いていたビューを記憶します。

エージェントが作業中のまま終了しようとすると、実行中のセッション数を示して確認を求めます。その後、開発サーバーを置き去りにすることなく、セッションとそこから起動したものをすべて終了します。

アプリを開き直すとタブが戻ってきます。各タブはディレクトリとエージェントが選択済みのランチャーとして戻り、クリック一つで始められます。セッション自体は再開されません。それをするとエージェントを思考の途中で再起動することになるからです。会話を取り戻したいときのために、すぐそこに `続行` があります。

ターミナルで別の場所に `cd` すると、これらすべてが追従します。Windows は例外で、他のプロセスのディレクトリを読み取る手段がないため、タブは開始したフォルダーのままで、ツールチップにもそう表示されます。

## 🖱️ 出力内をクリックする

エージェントは絶えずパスや URL を出力し、それらはすべて有効なリンクです。クリックすると開きます。Web リンク（URL、またはエージェントが描画したハイパーリンク）にポインターを重ねると、リンク先とそれを開くクリック方法が、ページのタイトル、概要、画像とともにタブの左下隅に表示されます。それらが届くまでは「プレビューを読み込み中…」と表示されます。クリックがプレビューを待つことはありません。タブ内のプログラムがマウスを読み取っている間（「クリック」タブのエージェントや、マウスを有効にした `vim` や `tmux`）はプログラムが通常のクリックを受け取るので、そこではリンクは **⌘ クリック**（Windows と Linux では **Ctrl クリック**）で開きます。そこではパスやプレーンな URL に下線は引かれませんが、エージェントが描画したハイパーリンクには引かれます。

| クリックするもの                                                    | Muster の動作                                                                                                   |
| ------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| エージェントが変更したファイル：`src/features/review/model/diff.ts` | レビューパネルで差分を開きます。出力に行番号があればその行までスクロールします                                  |
| 変更されていない画像のパス：`/tmp/shot.png`                         | プレビューのオーバーレイで開きます                                                                              |
| セッションのディレクトリ内にある変更されていないファイル            | ターミナル横のファイル列で開くので、読むためにタブを離れる必要はありません                                      |
| その他のパス：`src/entities/tab/model/deck.ts:187`                  | エディターで開きます。VS Code、Cursor、Antigravity IDE、Windsurf、VSCodium、Insiders はその行にもジャンプします |
| URL                                                                 | ブラウザーで開きます。`http` と `https` のみで、`mailto:`、`tel:` などのスキームは拒否されます                  |

行の順番は Muster が判定する順番です。変更されたファイルを指すパスは、他の何よりも先に差分として開かれます。そのため、エージェントが追加したばかりの画像は、オーバーレイではなくレビュー列で画像として開きます。画像の判定はファイル列より先に行われるので、セッションのディレクトリ内にある画像も、テキストとしてではなくオーバーレイで開きます。

パスはタブの現在のディレクトリを基準に解決されるので、絶対パスだけでなく `src/app/App.tsx` のようなパスも使え、`~` はホームを意味します。パスに下線が引かれるのは、区切り文字とファイル拡張子の両方を含む場合だけです。区切り文字の条件がなければ `package.json` に触れるすべての文が光ってしまい、拡張子の条件がなければエージェントがついでに口にするすべてのディレクトリが光ってしまいます。その代償として、`scripts/build` や `.github/CODEOWNERS` のような拡張子のないファイルにも下線は引かれません。

画像をターミナルのエスケープシーケンスとして出力するツールも動作します。Sixel と iTerm2 のインライン画像プロトコルの両方に対応しているので、`imgcat`、`chafa --format=sixel`、`timg` はその場で描画されます。

エージェントがハイパーリンクとして描画したリンク（Claude Code の `#604` のようなプルリクエストへのリンクや、複数行にまたがって折り返された長い URL）は、画面上のテキストではなく、リンクが持つ `http` または `https` のアドレスを開きます。そのため、開くページがテキストの示すページと同じとは限りません。ホバーしている間、隅のラベルに実際のホストが完全な形で、続いてアドレスが表示されます。メール内のリンクと同じように、テキストではなくそちらを読んでください。

## 🪣 ファイルをドロップする

タブにファイルをドラッグすると、そのパスが引用符付きで、後ろにスペースを付けてプロンプトに入力されます。30 年前からターミナルがドロップされたファイルを扱ってきた方法であり、「あのファイル」からそれを必要とするプロンプトへの最短経路です。複数ドロップすると、複数の引数になります。

引用符の付け方はタブで動いているシェルに合わせられ、WSL のタブにドロップしたファイルはディストリビューションが開けるパス（`C:\…` ではなく `/mnt/c/…`）として届きます。

## 🔍 変更をレビューする

`⌘G` または `Ctrl+Shift+G` で、右側にレビュードロワーが開きます。同じディレクトリを 2 つのビューで見るナビゲーターで、1 つ目のビューの下にコミット、プル、プッシュがあります。

**変更** には、差分のあるすべてのファイルが、ステータス文字と行数とともに一覧表示されます。**比較** ピッカーを使うと、未コミットの状態ではなくブランチと比較でき、その際は 2 つのブランチが分岐した地点と比較します。そのため、ベースブランチ自身のその後のコミットが、あなたの作業として表示されることはありません。エージェントが書いたばかりのファイルも一覧に含まれます。git はまだそれらを認識していませんが、最も読みたい変更はそれらだからです。

**ファイル** は作業ディレクトリの構造を、1 フォルダーずつ表示します。ドットファイルは **隠しファイル** を押すまで表示されません。`.github/` が見当たらないときもそこです。`.gitignore` にマッチするものは、隠すのではなく薄く表示されます。ビルドしたばかりの `dist/` は探しに行くものであり、作業の一部として読めてはいけないからです。**任意の行を右クリック** すると（ファイルでもフォルダーでも）メニューが開きます。Finder、エクスプローラー、またはファイルマネージャーで表示する、パスをコピーする、ディレクトリからの相対パスをコピーする、の操作ができます。メニューキーと `⇧F10` でキーボードから同じメニューを開け、矢印キーで項目を移動できます。

どちらのビューから選んだものも、**ターミナルとドロワーの間の列** で開きます。決してターミナルの上には重なりません。エージェントが変更したものを読むことと、次の指示を入力することは一続きの作業だからです。変更されたファイルは差分として開きます。2 つの行番号の余白があり、追加・削除された行は色付けされ、[Shiki](https://shiki.style) によってシンタックスハイライトされます。「コンテキスト」で各ハンク周辺の変更のない行を 12 行、またはファイル全体に広げられます。差分はターミナル自身のフォント、サイズ、行の高さ、文字幅で表示されます。コードを読むために選んだ設定こそ、差分を読むのにふさわしい設定だからです。ツリーから開いたファイルはそのままの内容で開きます。どちらの場合も **折り返し** で長い行を制御できます。単語そのものが長い行である場合は単語の途中でも折り返すので、ミニファイされたバンドルや base64 の塊も横スクロールせずに列に収まります。**行番号をクリックするとその行がエディターで開き**、Escape で列が閉じます。

画像は画像として表示されます。透明なロゴが見えなくならないよう市松模様の背景の上に表示され、変更された画像も「バイナリファイル」ではなくこの形で表示されます。

驚かないように知っておくべき制限が 2 つあります。5,000 行を超えるファイルや差分は、元の行数を示す 1 行を添えて切り詰められます。25 万個もの要素を描画するとウィンドウが固まってしまうからです。また、シンボリックリンクは辿って読まないので、リンクされたファイルはリンク先ではなく拒否のメッセージを表示します。**再読み込み** でファイルツリーを含む両方のビューが更新されます。

**ツリーから開いた Markdown はレンダリングされて開きます**。見出し、表、リスト、引用、Shiki でハイライトされたフェンス付きコード、そして ```mermaid の図は図として描画されます。「変更」の一覧から開いた Markdown ファイルは差分として開きます（変更を見たいと求めたのですから）。ヘッダーのボタンで両者を切り替えられ、ボタンには切り替え先が表示されます。レンダリングするなら **プレビュー**、戻るなら **ソース** または **差分** です。エージェントは大量の Markdown を書きますし、入れ子になった表のソースを読むことは文書を読むことではありません。文書内の何ものも勝手に動作することはありません。文書自身の HTML はエスケープされ、リンクはターミナルの URL と同じくブラウザーで開きます（URL はツールチップに表示されるので、開く前に確認できます）。画像は取得するのではなくディスクから読み込まれ、文書自身のフォルダー内にあるものに限られます。外部を指す画像は、読み込む代わりにその旨を表示します。

**どのパネルも左端をドラッグ** するとサイズを変更できます。端をダブルクリックすると元に戻り、ドラッグ中に Escape を押すとキャンセルされ、幅は次回のために記憶されます。履歴ドロワーも同じようにサイズを変更できます。3 つすべてを同時に開くことができ、どれだけ広くドラッグしても、ターミナルは自分の列を確保します。

**コミット、プル、プッシュ** は「変更」の一覧の下にあります。メッセージを入力してコミットボタンを押すか、`⌘Enter`（他の環境では `Ctrl+Enter`）を押します。何もステージされていなければ、新規ファイルを含むすべての未コミットの変更をコミットし、ボタンは **すべてコミット** と表示されます。ターミナルで一部をステージしていればそれだけをコミットし、ファイル数を表示します。**比較** ピッカーが変えるのは一覧の比較対象だけで、コミットに含まれるものは変わりません。コミットが失敗した場合（たとえばフックが拒否した場合）、ボタンがステージしたものは再びアンステージされるので、次の試行では修正が反映されます。デタッチ状態の HEAD では、コミットがどのブランチにも属さないことを警告したうえで、そのまま進めることもできます。編集のために停止した rebase もデタッチ状態だからです。

**プル** は fast-forward のみを行うので、エージェントが作業中のツリーにマージの途中状態を残すことはありません。ボタンには遅れているコミット数が表示され、上流のないブランチではグレーアウトされます。**プッシュ** には送信待ちのコミット数が表示されます。上流のないブランチや、別の名前のブランチを追跡しているブランチ（`git checkout -b fix origin/main` で作られるもの）では、代わりに **公開** と表示され、`main` に向けてではなく、そのブランチ自身の名前でプッシュしてそれを追跡します。送信先は `git push` 自体が送る先と同じです。`pushRemote` または `remote.pushDefault` を設定していればそこへ、そうでなければ追跡しているリモートへ、あるいはリポジトリにリモートが 1 つしかなければ、名前に関係なくそこへ送ります。フォークでの作業では、自分のフォークに公開し、ブランチはプル元のリポジトリを追跡したままになります。それ以降ボタンは **プッシュ** と表示され、フォークにまだないコミット数を数えます。どちらもデタッチ状態の HEAD では動作しません。履歴ドロワーにも同じプルとプッシュがあります。

git の実行中は、**キャンセル** で git とそこから起動したもの（フック、`ssh`）を停止できます。履歴ドロワーからのブランチ切り替えも対象です。git がすでに処理を終えていた場合（git は `post-commit` の実行前にコミットし、`post-checkout` の実行前に切り替えます）、ドロワーは"Cancelled."ではなくその旨を表示します。ファイルの書き込み中に切り替えやプルを止めると、ツリーが中途半端に更新された状態になることがあり、それは変更として表示されます。キャンセルするのは、本当に止まってしまったときだけにしてください。git が拒否した場合（フックが失敗した、リモートが更新された、認証情報がない）、ドロワーには git 自身のメッセージが表示されます。フックと認証ヘルパーには、ターミナルと同じく、ログインシェルが設定する `PATH` が渡されます。これはこれらのボタンのいずれかを初めて押したときに読み取られ、失敗した場合は 1 分後に再び読み取られます。macOS と Linux では git に入力を求めるためのターミナルが渡されないので、認証情報がない場合は待たずに失敗します。例外は gpg の pinentry で、これは gpg-agent が自ら開くため、他の環境と同じく応答を待ちます。そこから抜け出す手段がキャンセルです。

ドロワーや列でそれ以外に書き込みを行うものはありません。**すべてコミット** 以外でステージされるものはなく、変更の破棄も編集もできません。ファイルを編集するのはタブのエージェントであり、足元で書き換えられているファイルを別に編集可能なコピーとして持つことは、マージの競合を招くだけです。その代わりに、ファイルのパスをセッションに入力するボタンがあります。「これをもう一度見て」と伝える最速の方法です。パスのコピーとエディターで開く操作もあります。

## 🌿 履歴とブランチ

ブランチ名をクリックするか履歴のショートカットを押すと、右側にドロワーが開き、そのディレクトリのコミットが一覧表示されます。件名、ブランチとタグのバッジ、短い SHA、作成者、経過時間が並びます。リモートにまだないコミットにはドットが付きます。ディレクトリやブランチが変わると再読み込みされ、すぐに更新したいときのための再読み込みボタンもあります。

同じドロワーの **切り替え** では、代わりにブランチが、最近コミットされた順に絞り込みボックス付きで一覧表示されます。1 つ選ぶとチェックアウトします。リモートにしかないブランチも `リモート` の印付きで一覧に含まれ、選ぶとそこからローカルブランチを作成します。

ツリーに未コミットの作業がある場合、ドロワーは選ぶ前にその旨を表示します。チェックアウトがそれによって失敗する可能性があるからです。ただし失敗するのは、あなたが触れたファイルが 2 つのブランチ間で異なる場合だけなので、試すこと自体は止めません。git が拒否した場合は邪魔になっているファイルを列挙し、ドロワーはそれをそのまま表示します。

**プル** と **プッシュ** はドロワーのヘッダーの下にあり、レビュードロワーにあるのと同じ 2 つのボタンです。ステータスバーの `↑` と `↓` の数をクリックするとここに来ます。切り替えでは `git switch` を実行するため、git 2.23 以降が必要です。もうブランチではない名前を渡すと `git switch` は拒否しますが、`git checkout` はその名前をフォルダーと解釈し、保存していない作業の上からそれを復元してしまいます。

## 📍 自分の質問に戻る

あなたのメッセージには 2 種類の印が付きます。2 つの印はそれぞれ異なる問いに答えるからです。

スクロールバー自体には、各メッセージのセッション内での **実際の** 位置に小さな印が付きます。VS Code がスクロールバーに付ける色付きの印と同じ考え方です。右端に沿っては、代わりにドットの列が **等間隔** に並びます。メッセージ 1 件につき 1 つで、古いものが上です。そうしないと、長いセッションでは比例配置の印がすべて同じ数ピクセルに積み重なってしまいます。現在いる位置のドットは、輪郭ではなく塗りつぶしで表示されます。

ドットをクリックすると、そのメッセージにジャンプします。右下隅の `↑` と `↓` のボタンで同じ一覧を順に移動でき、最後のメッセージを越えると、どちらの方向でもスクロールバックの末尾または先頭まで進みます。クリック可能なタブには進む先のスクロールバックがないので、最も古いメッセージと最も新しいメッセージで止まります。

その横にある `⟳` は会話を再描画します。ウィンドウのサイズを変えたり、パネルを開いたりすると、ターミナルの列数が変わります。エージェント自身が描画した画面は、それに合わせて折り返し直すことができません。それによって生じるずれたブロックを見せる代わりに、Muster は履歴を破棄し、このボタンでエージェントに新しい幅で出力し直すよう求めます。サイズ変更の後に書き込まれたものは保持され、通常どおり印が付きます。出力し直されるのは、それ以前のものだけです。

このボタンはすべてのタブにあるわけではありません。シェルのタブは対象外です。出力は普通のテキストとして折り返されるのでサイズ変更にも耐えますし、開き直す会話もないからです。エージェントがシェルに戻したタブや、ターミナルが 1 画面分しか保持していないタブにもありません。クリック可能なタブは通常これに当たり、サイズ変更で損なわれる履歴がそもそもありません。「通常」と言うのは、ボタンがモードではなくバッファーに従うからです。独自のフルスクリーンレンダラーをオフにした CLI は通常のバッファーで動いて本物の履歴を作るので、`⟳` もそれとともに戻ってきます。また、エージェントがまだ何も記録していないディレクトリのタブにもありません。出力し直すものがないからです。

ドットは、プロンプトの内容ではなく描画のされ方（色付けされたセルのブロック）で見つけます。そのため、プロンプトをそのように描画する CLI であれば、Muster がその CLI について何も知らなくても機能します。知っておくべき帰結は次のとおりです。

- **通常のシェルからは何も得られません。** 既定の `bash` や `zsh` のプロンプトには色付けがないので、見つけるものがありません。逆に、最初の数列に色を付けるもの（差分の余白、色付きのログ）には印が付くことがあるので、ドットは「あなたが入力した証拠」ではなく「ここで何かが強調表示された」という意味に受け取ってください。
- **表示されるのは最新の 12 件程度だけで**、それもスクロールバックにまだ残っているものに限られます。
- **クリック可能なタブでは、ドットは画面からではなくエージェントから得られます。** フルスクリーンの TUI は代替スクリーンバッファー（1 画面分の高さで履歴なし）に描画するので、ドットが読み取れるものが画面上にありません。代わりに Muster は Claude Code 自身のトランスクリプトを読みます。こちらのほうが優れた情報源で、タブが存在する前に `--continue` が出力したものも含め、あなたが入力したすべてのメッセージが含まれます。ドットをクリックすると、エージェントのビューがそのメッセージまでスクロールして戻ります。ホイール操作を送ってテキストを探し、ビューが動かなければすぐに諦めます。エージェントがまだ出力している間は動きません。トランスクリプトを見つけるにはセッションの記録が必要なので、**セッションの出力を記録** をオフにすると、クリック可能なタブのドットも一緒になくなります。
- **クリック可能なタブにはスクロールバーがなく**、本物のスクロールバーを持つこともできません。そこではターミナルは 1 画面分しか保持せず、履歴はエージェントが保持しており、エージェントはその位置を一切報告しないからです。ドットがその中のある場所に戻る手段であり、ホイールでは引き続きエージェント自身のビューをスクロールできます。**スクロールバック** のタブにはターミナル自身のバーがあり、メッセージとファイルの印がその上に付きます。
- **タブは「スクロールバック」で始まります**。ターミナル自身が履歴を保持するモードで、スクロールバーとその印、検索バー、幅の修復はすべてそれを読み取ります。Claude Code 以外のすべてのエージェントでは、ドットにもそれが必要です。ステータスバー右側の **クリック / スクロールバック** の切り替えで、エージェントがマウスを受け取るモードにタブを切り替えられ、スタート画面でも起動ごとに同じ選択肢が提示されます。この切り替えは、エージェントがこのディレクトリで会話を記録した後に表示されます。記録がないと `--continue` は何も見つけられず、エージェントはモードを変える代わりにすぐに終了してシェルに戻ります（Windows PowerShell のタブではセッションが終了します）。切り替えはそのディレクトリの最新の会話を開き直すので、同じディレクトリの 2 つ目のタブでは、そのタブが実行していた会話ではない可能性があります。切り替えると `--continue` で会話を開き直すので何も失われず、新しいタブをどちらのモードで開くかは設定で選べます。切り替えで引き継がれるのは会話であってコマンドラインではありません。セッション開始時に指定した追加フラグは再現されず、これはステップ矢印の横にある⟳ ボタンと同じです。クリック可能なセッションではエージェントがマウスを受け取っているので、出力を選択してコピーするには、macOS では **Option ドラッグ**、それ以外では **Shift ドラッグ** が必要です。「スクロールバック」のタブでは、ブロック選択は通常どおり動作します。エージェント自身のビューで選択した内容はエージェントがコピーし、あなたのクリップボードにも入ります。

  「クリック」モードは道を空けるだけです。Claude Code は依然として自分でレンダラーを選び、マウス操作を報告するのはフルスクリーンレンダラーからだけです。さらに、フルスクリーンレンダラーの起動に失敗すると自らそれをオフにし、Muster が何を設定してもそれを元に戻すことはできません。そのため、「クリック」タブでクリックしても何も起きない場合は、そのセッションで `/tui fullscreen` を実行してください。

## 🗂 出力内の現在地を知る

長いセッションをさかのぼってスクロールすると、周囲の出力が扱っているファイルの名前を示すラベルがスクロールバーに沿って上がってきます。画面に表示されている部分より上でエージェントが出力した、最も近い `Updated …` または `Created …` の行です。ラベルはスクロールバーのつまみと同じ高さに表示されるので、バーはどれだけさかのぼったかを、ラベルは何を見ているかを示します。`↑`/`↓` ボタンのある下端付近では脇に退きます。

ラベルをクリックすると、そのファイルがターミナル横のリーダーで開きます。

セッションで名前の挙がったすべてのファイルには、スクロールバー自体にも灰色の印が付きます。あなた自身のメッセージの印の横に並び、そちらは送信先のエージェントの色で表示されるので、一目で作業が行われた場所がわかります。各印の高さはそのファイルに触れた出力の長さと同じで、バーの左端だけを占めるので、2 種類の印は色だけでなく形でも区別できます。

レビューパネルも自分のスクロールバーに印を付けます。変更されたファイルを開くと、編集箇所がバーに緑と赤の帯で表示され、余白には変更された各行の横に緑のバーが付きます。そのため、3 行だけ変更された長いファイルでも、スクロールして探す必要はありません。

これはコードではなく出力を読むので、インデックスも設定も不要です。エージェントがファイル名を出していなければ、何も表示しません。

## 🔎 スクロールバックを検索する

`⌘F` または `Ctrl+Shift+F` で、ターミナルの上に検索バーが開きます。入力するにつれて最初の一致にジャンプし、Enter と `⇧Enter` で残りを順に移動できます。件数は `3 / 17` のように表示され、Escape で閉じるとキーボードがエージェントに戻ります。一致箇所はグリッド内でハイライトされ、スクロールバーにも印が付くので、はるか上にある一致も見つけられます。

エージェントは何百行も出力し、肝心のエラーはいつもスクロールして見えなくなったところにあるものです。

## 📋 大きなテキストを貼り付ける

2,000 行のログや長い差分をセッションに貼り付けると、2,000 行分のキー入力として届き、エージェント自身のエディターがそれを再整形することになります。エージェント CLI が大きな貼り付けを後から開けないプレースホルダーに折りたたむのはそのためです。Muster は代わりにそれをファイルに書き出してパスを入力するので、エージェントはファイルツールでそれを読み、後からでもそのファイルは残っています。5,000 文字未満のものは、これまでどおりそのまま貼り付けられます。

ファイルはセッションの記録の横に置かれ、記録とともに期限切れになります。OS がエージェントがパスを読む前に消去しかねないシステムの一時ディレクトリには置かれず、エージェントが行っていない変更として表示されてしまうリポジトリ内にも置かれません。

## ⚠️ 2 つのタブが同じファイルに触れたとき

1 つのリポジトリで 2 つのエージェントを走らせると（2 つの worktree、2 つのブランチ）、両者が同じファイルを編集していることに最初に気づくのは、たいていマージの競合です。そのときには、両方を適用することのできない差分がすでに両方から作られています。Muster はすべてのタブを管理しているので、それが起きている最中に気づけます。ステータスバーにそのファイルと、それを持つ別のタブが表示されます。

_同じ_ ディレクトリのタブは対象外です。それらは 1 つの作業ツリーなので、定義上すべてのファイルを共有しており、常に表示されている警告は誰にも読まれません。

## 📼 過去のセッション

ターミナルのスクロールバックはウィンドウとともに消え、エージェント CLI は会話をそれぞれのピッカーの奥にしまい込みます。そのため「昨日このフォルダーで何をしていたか」を知るには、タブを離れて探しに行く必要があります。Muster は各セッションを実行中に記録するので、ステータスバーの **過去のセッション** ボタンで、このディレクトリで起きたことを一覧表示できます。どのエージェントか、最後に出力したのはどれくらい前か、どれだけ出力したかが表示されます。実行 1 回につき 1 行で、今いるタブでの実行も含まれます。

エージェントが会話の ID を公開している場合、その行には **このタブで再開** が表示されます。そこで実行中のものを終了し、エージェント自身の再開フラグを使って、その会話をその場で開き直します。Claude Code は ID を公開しますが、他のエージェントは公開しないので、それらの行には、何も言わずに新しいものを始めてしまうボタンを出す代わりに、その旨が表示されます。

このボタンは、ディレクトリがある限り表示されます。セッションの実行中にも、復元されたタブや終了したばかりのタブで次のセッションが始まる前にも表示されます。

セッションのあるタブでは、ドロワーの上部に **ここで新しいセッション** も表示されます。まだ実行中のものを終了し、ディレクトリとエージェントが入力済みのスタート画面にタブを戻します。一覧が投げかける問いのもう半分です。まだ何も開始していないタブはすでにその画面を見ているので、そこには表示されません。

記録は出力そのままなので、エージェントが出力したものはすべて含まれます。画面に表示された秘密情報も含まれ、あなたの権限で動くものなら何でもそれを読めます。記録は設定で切り替えられ、各セッションは末尾を残して 4 MB までに制限され、記録は設定した保持期間の後に削除されます。何かがどこかに送信されることはなく、現在記録の内容を表示する機能もありません。一覧は各ファイルのサイズと経過時間から作られます。

## 🪟 ウィンドウは閉じたときのままに

Muster は各ウィンドウのサイズ、位置、最大化していたかどうか、そしてその中のタブを記憶するので、再起動すると、既定のウィンドウ 1 つではなく、使っていたウィンドウが開き直されます。

タブをタブ列からドラッグし、別のウィンドウのタブ以外の場所で離すと、そのタブ専用のウィンドウになります（Chrome と同じく、自分のウィンドウの上で離しても同様です）。別のウィンドウのタブの上で離すと、そこに移動します。タブを右クリックして **新しいウィンドウに移動** を選べば、ドラッグせずに同じことができます。ポインターにはタブの行き先を示すラベルが付いてきて、合流先のウィンドウはタブ列にその位置を示します。ウィンドウの唯一のタブをドラッグすると、ウィンドウ全体が移動します。カーソルやウィンドウの位置をアプリに知らせない Wayland では、ドラッグしたタブを専用のウィンドウにすることはできますが、ラベルは表示されず、単独のタブはウィンドウを運ばず、タブを別のウィンドウのタブの上にドロップすることもできません。実行中のエージェントやシェルは画面上のすべてとともに移動し、動き続けます。何も再起動しません。ウィンドウの最後のタブを閉じると、Chrome と同じくウィンドウが閉じます。最後のウィンドウを閉じるとアプリが終了します。どちらの場合も、そのウィンドウでまだ実行中のセッションがあれば、先に確認を求めます。他のウィンドウが開いたまま閉じたウィンドウは、そのタブも一緒に持っていきます。

2 回起動すると、2 つ目のコピーを開く代わりに、すでにあるウィンドウにフォーカスします。2 つのコピーは同じタブを復元し、そのすべてで独自のセッションを開始し、互いの記録を上書きしてしまうので、これは重要です。また、アプリが開いている状態でシェルから `muster ~/some/project` を実行すると、そのディレクトリで開始する準備ができたタブが開きます。開始はせず、準備した状態にとどめます。フォルダーを求めることは、そこでエージェントを実行することを求めることではないからです。

## 🐚 シェルだけを使う

スタート画面にはエージェントが一覧表示されます。その一覧の下、モードボタンの上に **代わりに通常のシェルを開く** があります。シェルはエージェントの一つではないからです。フラグもモードも、再開するものもありません。macOS でウィンドウを最小化しても、Dock のアイコンをクリックすれば戻ります。最後のウィンドウを閉じるとアプリが終了します。

**zsh または bash** のタブには、エージェントのタブでは役に立たない機能が 2 つあります。2 文字入力すると、同じ文字で始まる過去のコマンドがカーソルの下に新しい順で表示され、先頭のものはカーソルの先にも灰色で描画されます。`→` でそれを採用し、`↓` で一覧を下に、`↑` で上に移動します。Enter は選択した行を実行せずに入力し、Escape で一覧を閉じます。何も入力していないプロンプトでの `↑` は引き続きシェル自身の履歴で、修飾キー付きのキー（単語単位で移動する `⌥→`、改行する `⇧Enter`）は常にシェルに届くので、普段の操作は何も変わりません。候補は、まずこのセッションですでに実行したコマンドから新しい順に、次にシェル自身の履歴ファイルから取られます。シェルが履歴ファイルの場所をアプリに伝えるので、`HISTFILE` を移動していればそちらが読まれます。1 分前に実行したコマンドは、ファイル内のどれよりも先に候補になります。ファイルにはシェルが終了するまで現れないからです。

終了したコマンドにポインターを重ねると、その最初の行の右側に **出力をコピー** が表示されます。クリック一つで、何も選択せずに、そのコマンドが出力したすべてをクリップボードに入れられます。`⌘⇧O`（`Ctrl+Shift+O`）で、最後に終了したコマンドに対して同じことができます。

どちらの機能も、1 つのコマンドがどこで終わり次のコマンドがどこで始まるかをアプリが知っている必要があり、それを有効にするのが設定の **シェル統合** です。次に開くシェルのタブ（およびエージェント終了時にエージェントのタブが渡すシェル）を、それらの位置を報告する Muster 独自の起動ファイルで開始します。起動ファイルがあるのは zsh と bash だけで、それもホスト上に限られるので、PowerShell、fish、WSL のタブは何も報告せず、どちらの機能も使えません。ご自身の設定は何も変わりません。起動ファイルはまずあなたの設定を読み込み、その後に印を追加します。

## 🚫 フォルダーを読み取れないとき

アプリが一覧表示を許可されていないフォルダーでセッションを開始すると、Muster はその旨を表示します。シェルが失敗し、`brew`、`mise`、エージェントがそれぞれ別々にディレクトリが「存在しない」と訴えるのに任せることはしません。警告した後は邪魔をしません。同じボタンをもう一度クリックすると、それでもそこでセッションを開始します。一覧表示できないフォルダーが、作業できないフォルダーだとは限らないからです。

macOS ではこれがよくある原因です。`~/Documents`、`~/Desktop`、`~/Downloads` には許可が必要で、**その回答は記憶されます**。そのため、確認ダイアログを「許可しない」で閉じてしまうと、もう一度試してもダイアログは戻ってきません。Muster はその旨を伝え、プライバシー設定に直接移動するボタンを表示するので、そこで再びオンにしてください。アプリは Developer ID で署名されていないため、macOS は新しいバージョンをそれぞれ別のソフトウェアとして扱い、アップデート後に再び尋ねます。

Windows では、フォルダー自体のアクセス許可によって拒否されるか、「ドキュメント」「デスクトップ」「ピクチャ」の下にある場合はコントロールされたフォルダー アクセスによって拒否されます。Linux ではファイルのアクセス許可か、Flatpak または Snap のサンドボックスが原因です。

## 🔔 通知

エージェントがターンを終えて制御を返したとき、それが知らせを受けるタイミングです。

- タブのドットが点灯して脈動し、
- デスクトップ通知がエージェントとタブの名前を示し、エージェントが公開していれば最後の言葉を引用します。

エージェントはそのタイミングを 2 つの異なる方法で告知します。ターミナルのベルを鳴らすものもあれば、代わりに構造化されたイベントを送るものもあり、Muster は両方を読み取ります。ベルには何も必要ありません。Claude Code のセッションが使う構造化イベントは、その CLI にインストールするフックプラグインから送られるので、プラグインのないセッションでも点灯したままの「入力待ち」ドットとステータスバーは表示されますが、脈動と通知はありません。API エラー（レート制限、過負荷）で終わったターンも、正常に終わったターンと同じように告知されます。

すでにそのタブを見ている間は何も通知されず、2 つの方法で告知されたターンは 1 つの通知になります。macOS、Linux、WSL では、終了したエージェントはタブを終了させずにシェルに渡し、その旨を独自の通知で知らせます。失敗した場合は終了コードも添えます。セッションの終了も同じように告知されます。タブを渡されたシェルの終了、または Windows PowerShell ではエージェント自体の終了です。これらはすべて調整でき、オフにすることもできます。

## ⚙️ 設定

設定のショートカットを押すか、ステータスバー右側の歯車をクリックします。設定はタブとして開き、変更はすぐに反映されます。すでに実行中のターミナルにも反映されます。ただし 3 つの設定はセッション開始時に読み取られるため、すでに動いているセッションではなく次のセッションから反映されます。**セッションの出力を記録**、**シェル統合**、**既定のターミナルモード** です。最後のものについては、すでに開いているタブを変更するにはステータスバーの「クリック / スクロールバック」の切り替えを使います。

- **言語**：English（US または UK）、繁體中文、简体中文、日本語。既定の _システムに合わせる_ は、OS の優先言語のうち Muster が対応している最初の言語に従い、それ以外の場合はアメリカ英語になります。切り替えてもセッションが再起動することはありません。
- **新しいタブ**：どのエージェントとディレクトリで開始するか、そしてタブを開くときの **ターミナルモード**。_クリック_ は Claude Code 自身のプロンプト、サブエージェント、シェルにマウスを渡し、ドットをそのトランスクリプトから読み取ります。_スクロールバック_ はターミナル自身の履歴を保持するので、検索バーと幅の修復が使えます。1 つのセッションで両方は使えません。ステータスバーの切り替えは、この設定を変えずに 1 つのタブだけを切り替えます。
- **ターミナル**：テーマ、フォント、サイズ、行の高さ、文字幅、スクロールバック、カーソルの点滅、そして **シェル統合**。シェル統合は zsh や bash のタブにコピー操作と補完をもたらします。リガチャは有効です。`->`、`=>`、`!==` を 1 つのグリフとして描画するフォントは、ここでもそのように描画されます。フォントの一覧はマシンにインストールされているすべての書体から、グリッドに揃えられるものに絞り込んだものです。**すべてのシステムフォントを表示** で残りも一覧に含められます。レビューパネルの差分とファイルも同じ書体で描画されるので、コードの列は横の出力とまったく同じように読めます。
- **背景**：ターミナルの背後に表示する画像。明るさのスライダーと、その上にサンプルの出力を表示するプレビューがあります。明るさは、背後にあるテキストとの対比でしか判断できないからです。
- **エディター**：ステータスバーのボタンでどのエディターを開くか。
- **通知**：通知するかどうか、見ているタブでは通知しないかどうか、サウンドを再生するかどうか。
- **Git**：ステータスを読み直す頻度と、履歴に読み込むコミット数。
- **セッションの記録**：セッションの出力を記録するかどうかと、その記録を保持する期間。
- **データ**：記憶したディレクトリの消去、またはすべての設定を既定に戻す。

WSL がインストールされた Windows では、**新しいタブ** で Windows とディストリビューションのどちらで実行するかも選べます。

## 🩹 問題が起きたとき

**ファイルをドロップしても何も入力されない。** 制御文字を含むパスは、入力されずに拒否されます。ブラケットペーストを終わらせるシーケンスがファイル名の一部になりうるからで、そうなると名前の残りがキー入力として届いてしまいます。そのファイルを使うつもりだった場合は、ファイル名を変更してください。

**聞いたこともない tap についての警告。** Homebrew 6 は、サードパーティの tap を信頼されるまで読み込むことを拒否し、マシン上の _すべての_ 信頼されていない tap を _すべての_ コマンドで列挙します。そのため、Muster と無関係な tap がインストール出力の中ほどを埋め尽くすことがあります。これはノイズであって失敗ではありません。最後に `successfully installed` があるかを確認してください。Muster 自体には `brew trust` は不要です。cask を明示的に指定することが、それを許可することになります。

**`brew tap ronny1020/tap` が `Cannot tap ronny1020/tap: invalid syntax in tap!` で失敗する。** 何も tap する必要はありません。インストールコマンドがそれを行います。tap を単独で実行すると、Homebrew の信頼のルールに引っかかります。tap する際に cask を検証し、信頼していない tap の cask の読み込みを拒否するからです。cask を名前で指定することが、その信頼を与えることになります。

**インストール直後にダブルクリックしても何も起きない。** macOS は、置き換えたばかりのアプリバンドルを登録するのに少し時間がかかります。もう一度開けば起動します。

**`brew install` が `Warning: Not upgrading muster, the latest version is already installed` と表示し、アプリはある。** これは Homebrew がすでにインストール済みだと伝えているだけで、エラーではありません。何もする必要はありません。それでも新しいコピーを強制的に入れたい場合は、`brew reinstall --cask ronny1020/tap/muster` を使ってください。

**`brew install` が「already installed」と表示するのに、アプリがない。** アプリが手動で削除されたため、Homebrew の記録とディスクの内容が食い違っており、`brew install` は何もインストールせずに成功を報告し続けます。`brew reinstall --cask ronny1020/tap/muster` で修復し、その後、上記と同じように quarantine 属性を消去してください。

**セッション開始時に「command not found」と表示される。** そのエージェントの CLI がインストールされていないか、ログインシェルが設定する `PATH` 上にありません。上の表のコマンドがご自身のターミナルで動くかを確認してください。

**デスクトップ通知が届かない。** OS が尋ねたときにアプリに通知の許可を与えるか、後からシステム設定で許可してください。Claude Code のタブで、タブのドットが点灯したままなのに通知が来ない場合、その CLI には通知プラグインがインストールされていません。ドットはセッション自身の出力から読み取るので何も必要ありませんが、通知にはプラグインが必要です。Claude Code のセッション内から `/plugin marketplace add warpdotdev/claude-code-warp`、次に `/plugin install warp@claude-code-warp`、次に `/reload-plugins` を実行してインストールしてください。再読み込みするまでは何もしません。また、すべてのフックが `jq` を経由するため、`PATH` 上に `jq` が必要です（`brew install jq`、またはお使いのシステムのパッケージマネージャー）。**WSL** のタブは、Windows の `WSLENV` に `WARP_CLI_AGENT_PROTOCOL_VERSION` と `WARP_CLIENT_VERSION` が含まれていない限り通知を受けません。その場合でも、エージェントの終了、セッションの終了、ベルを鳴らしたエージェントは告知されますが、ターンの終了は告知されません。

**エージェントのタブがすぐにシェルのプロンプトに戻ってしまう**（Windows PowerShell のタブでは、すぐに `終了 1` と表示される）。エージェント自体が起動を拒否しています。フラグが間違っている、CLI がインストールされていない、などです。プロンプトの上にあるエージェント自身の出力に理由が書かれています。修正してそのシェルでコマンドを再実行するか、タブの **スタートに戻る** ボタンを使ってください。このボタンは `exit` と入力すると表示され、PowerShell ではすぐに表示されます。

## 🔒 データについて

設定、記憶したディレクトリ、ドラッグしたパネルの幅はアプリが保存します。編集できる設定ファイルはまだありません。ほかに 3 つのものがディスクに保存され、いずれも設定 → セッションの記録 の保持期間が過ぎると期限切れになります。すべてのセッションが出力したものをそのまま記録したもの、各記録の横に置かれエージェントと会話の名前を示す小さなファイル、そして大きすぎる貼り付けのコピーです。記録は **既定でオン** で、同じ場所にスイッチがあります。貼り付けのコピーにスイッチはなく、ファイルになるほど大きな貼り付けがあるたびに書き出されます。記録に何が含まれるかは、上記の「過去のセッション」を参照してください。レビュードロワーとファイル列が読み取るものは、すべてあなた自身のディスク上のものです。ファイルの _内容_ は開いたときに読み取られ、レビュードロワーは新規ファイル（git がまだ認識していないもの）を、追加される行数を数えるために、最初の数百件まで読み取ります。これが起きるのは、数値を表示している「変更」ビューのときだけです。ファイルツリーでドロワーを開いた場合は、どのファイルに差分があるかを git に尋ねるだけで、どのファイルも読み取りません。ターミナルでパスをクリックした場合も git に同じことを尋ね、そのファイルが Muster 自身が表示するものであれば、そのファイルを読み取ります。つまり、求められた画像として表示される画像か、セッション自身のディレクトリ配下のどこかに解決され、ターミナル横の列で開くファイルです。最後の判定は解決後のパスとディレクトリの比較で、現在は前方一致です。エージェントが `../` を含めて書いたパスでもそれを満たしうるので、境界ではなく「エージェントが示した場所」として扱ってください。

Muster 自身を通じてマシンの外に出るものが 1 つあります。Web リンクにポインターを重ねると、ホバープレビューのためにそのページのタイトルと画像を取得します（上記の「プライバシー」を参照）。ターミナルやレンダリングされた文書で開いた Web アドレスはブラウザーに渡され、実行するエージェントはあなたが選んだエージェントです。
