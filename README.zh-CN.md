# Muster

[English](README.md) · [繁體中文](README.zh-TW.md) · **简体中文** · [日本語](README.ja.md)

**为 AI 智能体 CLI 打造的终端。**

`claude`、`codex` 和 `agy` 的运行方式与在你平常用的终端里完全一样——真正的 PTY、完整的 TUI、颜色、键盘，一应俱全。Muster 补上的是终端本身无从知晓的那部分：某个标签页里运行的是哪个智能体，它有没有值得恢复的对话，它什么时候停下来等你回来，以及你在看另一个标签页时它对你的工作区做了什么。

标签页并不是重点——Windows Terminal 和 PowerShell 早就有了。重点在于 Muster 知道标签页 _里面_ 是什么：

- 🎯 **启动界面先问你用哪个智能体**，再提供“新会话”“继续”或“恢复”——并把会失败的选项置灰，因为它会先检查该目录里有没有记录过的对话，而不是让 CLI 打印出 `No conversation found to continue`。凡是能读取智能体自身存储的地方——目前是 Claude Code——“恢复”会直接在页面上列出对话，每条都标着你当初问它的第一句话，因此选中一个只需点一下，而不必在 CLI 自带的选择器里耗上一整个会话。
- 🧹 **每个标签页都会清除智能体的会话标记**，这样从另一个智能体内部启动的智能体仍会记录自己的对话记录。否则日后 `--continue` 什么也找不到。
- 🐚 **会话通过登录 shell 运行**，因此由你自己的 profile 安装的 CLI——mise、nvm、`~/.local/bin`——都能被找到。否则 GUI 应用只会继承一个光秃秃的 `PATH`，这些都不存在。在 macOS、Linux 或 WSL 上退出智能体后，标签页会把那个 shell 交给你，仍在同一目录，就像在任何其他终端里退出它一样——智能体的输出仍保留在提示符上方，处于“回看缓冲”标签页中。此后标签页就表现得像一个 shell 标签页：“点击 / 回看缓冲”控件和 ⟳ 会消失，因为它们会结束这个会话；若开启了 **Shell 集成**，它还会获得 shell 标签页拥有的复制控件和补全。在 Windows PowerShell 下，标签页会随智能体一起结束。
- 🟠 **每个标签页上的圆点表明其智能体是否在工作**——会话仍在输出时闪烁，一旦安静下来、等你回应就变为实心。它读取的是输出本身，所以对每种智能体和普通 shell 都有效。
- 🔔 **智能体完成后会在其标签页上亮起圆点，并发出桌面通知**——前提是这一轮的结束有所通告，对 Claude Code 而言靠的是你安装的一个插件——因为同时运行好几个的意义就在于你不必盯着这一个。
- 🌿 **页脚会随智能体的改动跟踪目录及其 git 状态**，侧栏无需离开标签页即可切换分支。
- 🔍 **点击智能体刚改过的文件，它的差异就会在终端旁打开**，带语法高亮，旁边还有文件树。审阅智能体做了什么，是运行智能体的另一半工作。
- 🖱️ **输出中的路径、URL 和图片都可以点击。** 智能体的输出里到处都是这些；把文件拖到标签页上则会输入它的路径。

_To muster_：召集一支队伍，并对其检阅一番。启动界面负责召集智能体；状态栏和历史记录侧栏负责检阅。

可在 macOS、Windows 和 Linux 上运行。在 Windows 上，标签页可以在 WSL 中运行。

## 📦 安装

在 macOS 和 Linux 上，下载的就是整个应用。在 Windows 上，如果机器上还没有 Microsoft 的 WebView2 运行时，安装程序会自动获取。

Muster 不会自动更新——它没有更新程序，也不向任何地方回传数据，这正是下文“隐私”一节所承诺内容的另一半。

### 🍎 macOS

#### 安装

```bash
brew install --cask ronny1020/tap/muster && xattr -cr /Applications/Muster.app
```

作为一行命令运行。它会添加 tap、安装应用，并清除隔离属性——否则 macOS 会拒绝打开它。然后从“应用程序”中启动 Muster。

也可以从 [Releases 页面](https://github.com/ronny1020/muster/releases)下载 `.dmg`：把它拖到“应用程序”，然后运行同样的 `xattr -cr /Applications/Muster.app`，或在第一次打开时右键点击 → _打开_。

#### 更新

```bash
brew update && brew upgrade --cask muster && xattr -cr /Applications/Muster.app
```

刷新 tap 的是 `brew update`；没有它，Homebrew 会拿上次见到的版本来比较，并报告无事可做。之所以还要再执行一次 `xattr -cr`，原因与安装时相同：升级会放下一份全新的、被隔离的副本。

**之后 macOS 会再次询问文件夹权限，这是正常的。** 该应用使用 ad-hoc 签名，因此 macOS 通过二进制文件的哈希来识别它，把每个版本都当作从未见过的软件。已授予的权限不会延续。如果你关掉了提示，请看 [文件夹无法读取时](#-文件夹无法读取时)——你的回答会被记住，所以应用无法再问第二次。

如果你期望有新版本，升级却报告最新版本已经安装，请看[如果出现异常](#-如果出现异常)中的说明。

#### 卸载

```bash
brew uninstall --cask ronny1020/tap/muster
```

把应用拖进废纸篓会留下 Homebrew 对它的记录，之后 Homebrew 会报告该应用已安装，而实际上并没有。

### 🪟 Windows

#### 安装

```powershell
scoop bucket add ronny1020 https://github.com/ronny1020/scoop-bucket
scoop install muster
```

也可以从 [Releases 页面](https://github.com/ronny1020/muster/releases)运行 `_x64-setup.exe`。SmartScreen 会称其为无法识别的应用：选择 **更多信息 → 仍要运行**。它为当前用户安装，所以不会弹出管理员权限提示。

#### 更新

```powershell
scoop update
scoop update muster
```

单独的 `scoop update` 只刷新 bucket；真正更新应用的是第二行。

#### 卸载

```powershell
scoop uninstall muster
```

通过 `.exe` 安装的版本则在 **设置 → 应用** 中卸载。

所有文件都来自 [Releases 页面](https://github.com/ronny1020/muster/releases)。

### ⚠️ 为什么会有警告

本项目没有购买代码签名证书——Apple Developer 会员资格和 Windows 证书都要花真金白银，而它目前还没有用户来证明这笔开销值得。所以 macOS 看到的是一个只有 ad-hoc 签名的应用，Windows 看到的是一个未签名的安装程序，两者都会如实提示。

在 macOS 上，这也是安装命令以 `xattr -cr` 结尾的原因：Homebrew 会隔离它安装的每个 cask，而 Gatekeeper 拒绝打开未经公证的隔离副本。Homebrew 6 移除了过去用来跳过这一步的 `--no-quarantine` 参数。

作为签名的替代，你得到的是：每个二进制文件都由 GitHub Actions 根据它所声称的 tag 公开构建，所用的 workflow 你可以自行查看（[`.github/workflows/release.yml`](.github/workflows/release.yml)）。Homebrew 和 Scoop 这两条途径还会额外校验其清单中记录的校验和。

### 🕶️ 隐私

Muster 自己只发出一种网络请求：鼠标指针停在网页链接上时，它会获取该页面以及页面所指定的图片，用于悬停预览——链接指向任何地址都会如此，包括 `localhost`。Stack Exchange 的问题则改为向 `api.stackexchange.com` 请求，其站点图标向 `cdn.sstatic.net` 请求。你点击的链接会在浏览器中打开，由浏览器发出那个请求。它没有遥测、没有更新检查，也没有账户——它在本地读取你的文件系统和 git 状态，并运行你指定的 CLI。这些 CLI 确实会按各自的条款与各自的服务商通信，和在你平常的终端里完全一样。侧栏里的 **拉取** 和 **推送** 会用你自己的 `git` 访问你自己的远程仓库，且只在你按下它们时才会执行。

智能体 CLI 是独立的，Muster 有意不捆绑它们。你用哪个就装哪个——`claude`、`codex`、`agy`——并先确认每个都能在你自己的终端里运行；Muster 查找它们的方式与你的 shell 完全相同。

若想从源码构建，只需几条命令，需要 Bun 和 Rust 工具链：请参阅 [CONTRIBUTING.md](CONTRIBUTING.md)。

## 🚀 使用方法

新标签页会打开一个起始界面：选择一个 **文件夹**（最近用过的点一下即可，也可以浏览选择）、一个 **智能体**——输入文字即可筛选列表，因为一共有九个——以及会话的打开方式。shell 不在其中；它的按钮位于智能体列表和模式之间。Claude Code 在那里还提供 **终端模式**：“回看缓冲”或“点击”，默认值取自“设置”中指定的那个。选择一种模式，终端就会接管该标签页。

| 智能体      | 命令            | 新会话 | 继续       | 从过去的会话中选择      |
| ----------- | --------------- | ------ | ---------- | ----------------------- |
| Claude Code | `claude`        | ✓      | 最近一次   | 在 Muster 中列出        |
| Codex       | `codex`         | ✓      | 最近一次   | 它自己的选择器          |
| OpenCode    | `opencode`      | ✓      | 最近一次   | —                       |
| Gemini CLI  | `gemini`        | ✓      | —          | —                       |
| Goose       | `goose session` | ✓      | 最近一次   | —                       |
| OpenClaw    | `openclaw`      | ✓      | —          | —                       |
| Hermes      | `hermes`        | ✓      | —          | —                       |
| Aider       | `aider`         | ✓      | —          | —                       |
| Antigravity | `agy`           | ✓      | 上一次对话 | 在其 TUI 中用 `/resume` |

其中两个命令名与不相关的工具重名——`goose` 也是一个数据库迁移 CLI，`hermes` 是 React Native 的 JavaScript 引擎。Muster 运行的是你的 `PATH` 中最先找到的那个，所以如果某个标签页启动了错误的程序，原因就在这里。

“继续”一栏中的破折号表示该 CLI 没有为此提供文档化的参数，而不是 Muster 忘了：CLI 不支持的参数会让它拒绝启动，所以这种模式宁可不提供，也不去瞎猜。其中有几个反正会保存自己的历史，并在你启动它们时接上。

**恢复** 会在这里而不是在终端里打开列表。每一行都是该目录中过去的一段对话，最新的在前，标题是你在其中输入的第一句话——点击其中一行，智能体就会直接进入那段对话。列表显示最新的 30 段；如果某个目录的对话更多，最后一行会打开 CLI 自带的选择器，其余的都在那里。这依赖于读取智能体自身的存储，所以目前只支持 Claude Code，也只有在那里，没有历史的目录才会把这个模式置灰。Codex 仍像往常一样在会话内部打开它自己的选择器，而上表中“从过去的会话中选择”一栏为空的智能体则没有选择器可打开。

**改为打开普通 shell** 用于你想在同一个窗口中打开一个普通终端的时候——它不接受任何参数，因为没有程序可以传递，这也是它位于智能体列表旁边而不是列表之中的原因。

**尚不存在的目录** 不算错误：Muster 会提出创建它（连同父目录），并在你确认后在那里启动会话。`~` 表示主目录，所以 `~/code/new-thing` 会落在你预期的位置。

**额外参数** 会把其他任何内容原样传递过去——比如 `--model opus`。带引号的值会保持完整。

**你在看另一个标签页时，其他标签页会继续运行。** 不会重启，也不会丢失任何回看缓冲，所以让智能体自己干活、过一会儿再回来看，正是这个应用的常规用法。

**标签页就是标题栏。** 在 macOS 上，它们位于系统标题栏内部、红绿灯按钮后面；在 Windows 上则完全没有系统标题栏，最小化、最大化和关闭按钮绘制在标签栏右侧——这样窗口装饰只有一行，而不是上下叠两行。拖动标签栏可以移动窗口，双击则最大化，就像标题栏该有的那样。Linux 会在标签栏上方保留桌面环境自己的窗口装饰。

## 📊 状态栏

位于每个标签页底部：

- **目录**，用 `~` 缩写。点击它会打开文件树——它显示的是这棵树的名字，所以打开的就是这棵树。
- **分支**，没有分支时显示 `分离于 1a2b3c4`。点击它会打开历史记录侧栏。
- **`↑2 ↓1`**——尚未推送的提交，以及等待拉取的提交。点击它们会打开历史记录侧栏，因为提交就在那里。
- **`+3 ~5 ?2 !1`**——已暂存、已修改、未跟踪和冲突的文件，合为一个按钮。点击它会打开审阅面板的“变更”视图，因为这些文件就在那里。干净的工作区只显示“无更改”，点击也不会跳转。
- **`src/auth.ts 也在…中更改`**——另一个标签页同时在改动的文件。参见“两个标签页改动同一个文件时”。
- **点击 / 回看缓冲**——两个按钮，标签页当前所用的模式处于按下状态。按另一个即可切换。参见“跳回你问过的内容”。
- **“先前的会话”按钮**——此目录中记录过的对话，并提供回到其中一段的途径。参见“先前的会话”。
- **在 … 中打开**——在你的编辑器中打开当前目录。它会在 VS Code（包括 Insiders）、Cursor、Antigravity IDE、Windsurf、Zed、Sublime Text、JetBrains 系列 IDE、VSCodium、Neovim 或 Vim 中找到你装了的那些，并由“设置”决定用哪个。在 macOS 上，即使没有对应的 shell 命令也能找到已安装的编辑器——VS Code 的 `code` 只有在你从其命令面板运行过 “Shell Command: Install 'code' command” 后才存在，而大多数人从来没运行过。
- **齿轮图标**，位于最右侧，用于打开“设置”。每个标签页上都有状态栏，包括还没有启动任何东西的标签页，所以齿轮也总在那里。

这些控件都指明了自己显示的内容，而不是切换某个开关：文件树已经打开时再点击目录会关闭侧栏，但点击变更计数则会把它切换到“变更”视图。侧栏会记住你上次停留在哪个视图。

在智能体仍在工作时退出，会先征求你的确认，并告诉你有多少个会话在运行——然后结束它们以及它们启动的一切，而不是留下一个开发服务器在后台运行。

重新打开应用时，标签页会回来：每个都以启动界面的形式恢复，目录和智能体都已选好，点一下即可开始。会话本身不会被恢复——那会让智能体在思考到一半时重启——所以当你想找回的是对话时，“继续”就在那里。

在终端里 `cd` 到别处，这一切都会跟着你走。Windows 上除外，因为它无法读取另一个进程的目录：那里的标签页会停留在它启动时所在的文件夹，工具提示也会说明这一点。

## 🖱️ 点击输出中的内容

智能体不停地打印路径和 URL，而它们全都是可点击的：点一下就会打开。将鼠标悬停在网页链接上——无论是 URL 还是智能体绘制的超链接——会在标签页左下角显示它指向哪里、用哪种点击方式打开，以及页面的标题、摘要和图片，图片和文字到达之前显示“正在加载预览…”。点击从不等待预览。当标签页中的程序正在读取鼠标时——“点击”模式标签页里的智能体，或开启了鼠标的 `vim` 或 `tmux`——普通点击会交给它，所以在那里要用 **⌘ 点击**（Windows 和 Linux 上为 **Ctrl 点击**）来打开链接。在那里，路径和普通 URL 不会加下划线；智能体绘制的超链接则仍然有：

| 你点击的是                                            | Muster 的处理                                                                                     |
| ----------------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| 智能体改过的文件——`src/features/review/model/diff.ts` | 在审阅面板中打开它的差异；如果输出中给出了行号，则滚动到该行                                      |
| 它没有改过的图片路径——`/tmp/shot.png`                 | 在预览浮层中打开                                                                                  |
| 会话目录内一个未改动的文件                            | 在终端旁的文件栏中打开，这样阅读它不会让你离开该标签页                                            |
| 任何其他路径——`src/entities/tab/model/deck.ts:187`    | 在你的编辑器中打开；VS Code、Cursor、Antigravity IDE、Windsurf、VSCodium 和 Insiders 还会跳到该行 |
| URL                                                   | 在浏览器中打开——仅限 `http` 和 `https`；`mailto:`、`tel:` 及其他协议会被拒绝                      |

各行的顺序就是 Muster 提问的顺序：指向已改动文件的路径会先作为差异打开，之后才考虑其他情况，所以智能体刚添加的图片会以图片形式在审阅栏中打开，而不是在浮层中。图片的判断又排在文件栏之前，所以位于会话目录内的图片仍会在浮层中打开，而不是以文本形式显示。

路径相对于标签页的当前目录解析，所以 `src/app/App.tsx` 和绝对路径一样好用，`~` 表示主目录。只有同时包含分隔符和文件扩展名的路径才会加下划线：没有分隔符的话，每个提到 `package.json` 的句子都会亮起来；没有扩展名的话，智能体顺口提到的每个目录也会亮起来。代价是没有扩展名的文件——`scripts/build`、`.github/CODEOWNERS`——也不会加下划线。

以终端转义序列输出图片的工具同样可用：Sixel 和 iTerm2 的内联图片协议都受支持，所以 `imgcat`、`chafa --format=sixel` 和 `timg` 都能就地渲染。

智能体以超链接形式绘制的链接——比如 Claude Code 的 `#604` 拉取请求链接，或者被它拆成多行的长 URL——打开的是它所携带的 `http` 或 `https` 地址，而不是屏幕上的文字，所以打开的页面不一定是文字所指的那个。悬停时，角落的标签会先完整显示真实的主机名，再显示地址——要看的是它，而不是文字，就像对待邮件里的链接一样。

## 🪣 拖入文件

把文件拖到标签页上，它的路径就会被输入到提示符处，加上引号，后面跟一个空格——终端处理拖入文件的方式三十年来一直如此，这也是从“那个文件”到需要它的提示符之间最短的路径。拖入多个文件，就会得到多个参数。

引号的用法与标签页正在运行的 shell 相匹配；拖到 WSL 标签页上的文件，会以该发行版能打开的路径出现——`/mnt/c/…`，而不是 `C:\…`。

## 🔍 审阅变更

`⌘G` 或 `Ctrl+Shift+G` 会在右侧打开审阅面板。它是一个导航器，对同一目录提供两种视图，第一种视图下还有提交、拉取和推送：

**变更** 列出所有有差异的文件，带状态字母和行数统计。**对比** 选择器可以改为与某个分支比较，而不是与你未提交的状态比较；它比较的是两个分支分叉的那个点——所以基准分支自己后来的提交永远不会被当成你的工作。智能体刚刚写入的文件也在列表中；git 还没见过它们，但它们正是你最想读的变更。

**文件** 是工作目录的结构，一次展开一个文件夹。点文件默认不显示，直到你按下 **隐藏文件**，`.github/` 也在那里。凡是被 `.gitignore` 匹配的内容都会变暗而不是隐藏——你刚构建出来的 `dist/` 是你会去找的东西，但它不应看起来像是工作的一部分。**右键点击任意一行**（文件或文件夹）会弹出菜单：在访达、资源管理器或你的文件管理器中显示，复制路径，或复制相对于该目录的路径。菜单键和 `⇧F10` 可以从键盘打开同一个菜单，方向键则可在其中移动。

在任一视图中选中任何内容，都会在 **终端和侧栏之间的一栏** 中打开——绝不会盖住终端，因为阅读智能体改了什么和输入下一条指令是同一件事。改动过的文件以差异形式打开：两列行号、新增和删除的行带底色，由 [Shiki](https://shiki.style) 进行语法高亮，`上下文` 可将每个 hunk 周围的未改动行扩展到十二行或整个文件。它使用终端自己的字体、字号、行高和字符宽度——你为阅读代码选的是什么，差异就该用什么来读。从文件树打开的文件则显示其本身。无论哪种，**换行** 都控制长行——当一个单词本身就是那条长行时，它也会在单词内部断行，所以压缩后的 bundle 或 base64 数据块会折叠在栏内，而不是横向滚动——**点击行号会在你的编辑器中打开那一行**，按 Escape 则关闭该栏。

图片以图片形式显示——放在棋盘格背景上，这样透明的 logo 不会看不见——改动过的图片也会这样显示，而不是显示“二进制文件”。

有两个限制最好事先知道，免得被吓一跳：超过 5,000 行的文件或差异会被截断，并有一行说明原本有多少行，因为绘制二十五万个元素会让窗口卡死；符号链接不会被跟随读取，所以链接文件显示的是拒绝提示，而不是其目标内容。**重新读取** 会刷新两个视图，包括文件树。

**从文件树打开的 Markdown 会以渲染后的形式显示**：标题、表格、列表和引用，由 Shiki 高亮的围栏代码，以及绘制成图的 ```mermaid 图表。从“变更”列表打开的 Markdown 文件则以差异形式显示——你要求看的是变更——标题栏中的按钮可以在两者之间切换，并标明会切到哪里：**预览** 用于渲染，**源代码** 或 **差异** 用于切回来。智能体会写大量 Markdown，而阅读嵌套表格的源码并不等于阅读文档。文档中的任何内容都不能自行执行操作：文档自己的 HTML 会被转义，链接会在浏览器中打开，就像终端里的 URL 一样——工具提示中会显示 URL，让你在确定点击之前先看一眼——图片从磁盘读取而不是从网络获取，且仅限文档自己所在的文件夹。指向外部的图片会显示说明，而不会加载。

**拖动任一面板的左边缘** 可调整其宽度；双击边缘可恢复原状，拖动中按 Escape 可取消，宽度会被记住，下次沿用。历史记录侧栏也以同样方式调整宽度。三者可以同时打开，无论你把它们拖得多宽，终端都会保留属于自己的一栏。

**提交、拉取和推送** 位于“变更”列表下方。输入提交信息并按下提交按钮——或按 `⌘Enter`，其他平台上为 `Ctrl+Enter`。如果没有暂存任何内容，它会提交所有未提交的变更（包括新文件），按钮显示 **全部提交**；如果你在终端里只暂存了一部分，它就只提交那部分，并标明有多少个文件。**对比** 选择器只改变列表与什么比较，从不改变提交包含什么。如果提交失败——比如被某个 hook 拒绝——按钮暂存的内容会被重新取消暂存，这样下次尝试时会带上你的修复。在分离的 HEAD 上，它会警告这次提交不属于任何分支，但仍允许你继续——因编辑而停下的 rebase 也处于分离状态。

**拉取** 只做快进合并，所以它绝不会在智能体正在工作的目录树中留下合并到一半的状态，并会显示你落后多少个提交；在没有上游分支的分支上它会被置灰。**推送** 会显示有多少个提交等待推送。在没有上游分支的分支上，或者跟踪的是另一个名字的分支时——`git checkout -b fix origin/main` 就会造成这种情况——它会显示为 **发布**，以分支自己的名字推送并跟踪它，而不是推到 `main` 上。它推送到 `git push` 本身会推送的地方：如果你设置了 `pushRemote` 或 `remote.pushDefault` 就用它们，否则用它跟踪的远程仓库——或者仓库唯一的那个远程，不管它叫什么。在 fork 工作流中，它会发布到你的 fork，并让分支继续跟踪你拉取的那个仓库，从此按钮显示为 **推送**，计数的是 fork 还没有的提交。两者在分离的 HEAD 上都不可用。历史记录侧栏也有同样的“拉取”和“推送”。

git 运行期间，**取消** 会停止它以及它启动的一切——hook、`ssh`——包括从历史记录侧栏发起的分支切换。如果 git 已经完成了工作——它会在 `post-commit` 运行前提交，在 `post-checkout` 运行前切换——侧栏会如实说明，而不是显示 “Cancelled.”。在写入文件期间停止切换或拉取，可能让目录树只更新了一半，随后显示为变更；只在它们卡住时才取消。当 git 拒绝时——某个 hook 失败、远程已有新提交、缺少凭据——侧栏会显示 git 自己的消息。hook 和凭据助手看到的是你的登录 shell 设置的 `PATH`，和在终端里一样；它在你第一次按下这些按钮之一时读取，如果失败，一分钟后会再读一次。在 macOS 和 Linux 上，git 永远不会拿到一个可以弹出提示的终端，所以缺少凭据会直接失败而不是等待——gpg 的 pinentry 除外，它由 gpg-agent 自己打开，会像在其他任何地方一样等待回应。这时“取消”就是出路。

侧栏和文件栏中的其他东西都不会写入：除了 **全部提交**，没有任何东西会暂存文件，也没有丢弃和编辑功能——编辑文件的是标签页里的智能体，而一份正被底下改写的文件再多出一个可编辑副本，就是一场等着发生的合并冲突。它提供的是一个把文件路径输入到会话中的按钮——这是说“再看看这个”的最快方式——外加复制路径和在编辑器中打开。

## 🌿 历史记录与分支

点击分支名，或按下历史记录快捷键，右侧会打开一个侧栏，列出该目录的提交——主题、分支和 tag 徽标、短 sha、作者和时间。圆点标记出尚未推送到远程的提交。目录或分支变化时它会重新加载，如果你想早点刷新，还有一个刷新按钮。

同一侧栏中的 **切换** 会改为列出分支，最近有提交的在前，并带一个筛选框。选中一个即检出。只存在于远程的分支也会列出，标记为“远程”；选中这样的分支会基于它创建一个本地分支。

如果目录树中有未提交的工作，侧栏会在你选择之前提示，因为检出可能因此失败——不过只在两个分支在你改过的文件上有差异时才会失败，所以它并不阻止你尝试。当 git 拒绝时，它会列出挡路的文件，侧栏原样显示。

**拉取** 和 **推送** 位于侧栏标题下方，与审阅面板中的是同样两个按钮——状态栏的 `↑` 和 `↓` 计数也指向这里。切换运行的是 `git switch`，需要 git 2.23 或更高版本：给它一个已不再是分支的名字时，它会拒绝，而 `git checkout` 会把这个名字当成文件夹，并用它覆盖你未保存的工作。

## 📍 跳回你问过的内容

你的消息会被标记两次，因为这两种标记回答的是不同的问题。

在滚动条本身上，每条消息在会话中的 **真实** 位置都有一个小标记——和 VS Code 在其滚动条上放的彩色标记是同一个思路。沿着右边缘，则有一列 **均匀** 分布的圆点，每条消息一个，最早的在最上面：否则在一个很长的会话里，所有按比例排布的标记都会挤在同样几个像素里。你当前所在的那个圆点是实心的，其余是空心的。

点击圆点即可跳到那条消息。右下角的 `↑` 和 `↓` 按钮会逐条遍历同一个列表，越过任一方向的最后一条消息后，会继续跳到回看缓冲的末尾或顶部。在可点击的标签页中没有可以继续前往的回看缓冲，所以它们会停在最早和最新的消息处。

它们旁边的 `⟳` 会重绘对话。调整窗口大小——或打开一个面板——会改变终端的列数，而智能体自己绘制的画面无法重新折行以适应：与其让你看到由此产生的错位块，Muster 会丢弃历史，并由这个按钮请智能体按新宽度重新打印一遍。调整大小之后写入的内容都会保留并照常标记；只有之前的内容会被重新打印。

不是每个标签页都有它。shell 标签页不受影响——它们的输出像普通文本一样折行，所以经得起调整大小——而且它们没有可重新打开的对话。智能体已把标签页交还给你的 shell 时也没有它；终端只保留单屏画面的标签页也没有，可点击的标签页通常就是这样——没有可被调整大小破坏的历史。之所以说“通常”，是因为按钮跟随的是缓冲区而不是模式：关闭了自身全屏渲染器的 CLI 会在普通缓冲区中运行并积累真正的历史，`⟳` 也会随之回来。在智能体尚未记录任何内容的目录中的标签页上也没有它，因为没有可以重新打印的东西。

圆点是根据你的提示是如何绘制的——一块带底色的单元格——而不是它写了什么来找到的，所以对任何以这种方式渲染提示的 CLI 都有效，Muster 无需对它有任何了解。值得知道的是：

- **普通 shell 不会产生任何圆点。** 默认的 `bash` 或 `zsh` 提示没有底色，所以找不到任何东西。其他任何给开头几列着色的东西——差异的边栏、彩色日志——也可能被标记，所以请把圆点理解为“这里有东西被高亮了”，而不是你输入过它的证据。
- **只显示最近的十几条**，而且只显示仍在回看缓冲中的内容。
- **在可点击的标签页中，圆点来自智能体，而不是屏幕。** 全屏 TUI 绘制在备用屏幕缓冲区中——只有一屏高，没有历史——所以屏幕上没有任何东西可供圆点读取。Muster 改为读取 Claude Code 自己的对话记录，这是更好的来源：你输入的每一条消息，包括在标签页存在之前由 `--continue` 打印出来的那些。点击圆点会把智能体的视图滚回那条消息：它会发送滚轮事件并留意那段文字，如果视图不动就会很快放弃——智能体仍在输出时视图就不会动。找到对话记录需要会话记录，所以关闭 **记录会话的输出**，可点击标签页中的圆点也会随之消失。
- **可点击的标签页没有滚动条**，也不可能有真正的滚动条：终端在那里只保留单屏画面，历史由智能体持有，而它从不报告当前位置。圆点就是你回到其中某处的方式，滚轮仍会滚动智能体自己的视图。处于 **回看缓冲** 模式的标签页则有终端自己的滚动条，上面带有消息和文件标记。
- **标签页默认以“回看缓冲”模式启动**，由终端自己保存历史——滚动条及其标记、查找栏和宽度修复读取的都是它，Claude Code 之外的所有智能体要有圆点也都需要它。状态栏右侧的 **点击 / 回看缓冲** 控件可将标签页切换到由智能体接管鼠标的模式，起始界面也为每次启动提供同样的选择。该控件在智能体已在此目录中记录过对话后才会出现——若没有记录，`--continue` 什么也找不到，智能体会直接退出到你的 shell（在 Windows PowerShell 标签页中，会话会结束），而不是切换模式。它重新打开的是该目录最近的一段对话，在同一目录的第二个标签页中，这可能不是那个标签页原本在跑的对话。切换会用 `--continue` 重新打开对话，所以不会丢失任何内容；新标签页以哪种模式打开由“设置”决定。切换带走的是对话，而不是命令行：会话启动时带的额外参数不会重放，这一点与步进箭头旁的 ⟳ 按钮相同。在可点击的会话中，智能体接管了鼠标，所以要选中输出来复制，在 macOS 上需要 **Option 拖动**，在其他平台上需要 **Shift 拖动**；在“回看缓冲”标签页中，块选择照常可用。你在智能体自身视图中选中的内容会由智能体复制，同样会进入你的剪贴板。

  “点击”模式只负责让开道路。Claude Code 仍会自己选择渲染器，并且只在全屏渲染器中报告鼠标事件——而且全屏渲染器启动失败后，它会自行将其关闭，Muster 设置的任何东西都无法撤销这一点。所以如果在“点击”标签页中点击没有反应，请在该会话中运行 `/tui fullscreen`。

## 🗂 知道自己在输出中的位置

在一个很长的会话中往回滚动时，滚动条旁会有一个标签随之上移，标明你周围这段输出涉及的文件——即智能体在屏幕内容上方打印的最近一行 `Updated …` 或 `Created …`。它与滚动条滑块处于同一高度，所以滚动条告诉你回溯了多远，标签告诉你正在看什么。靠近底部时它会让开，因为那里是 `↑`/`↓` 按钮。

点击标签即可在终端旁的阅读栏中打开该文件。

会话提到的每个文件也会以灰色标记在滚动条上，就在你自己消息的标记旁边，而后者的颜色是你发送消息的那个智能体的颜色——所以扫一眼就知道工作发生在哪里。每个标记的高度与涉及该文件的输出一样高，并且只占滚动条的左边缘，所以两类标记除了颜色不同，形状也不同。

审阅面板也会标记自己的滚动条：打开一个改动过的文件，改动会以绿色和红色色带的形式沿滚动条显示，每个改动行旁的边栏里还有一条绿色竖条，所以一个只改了三行的长文件，不必滚动着去找它们。

它读取的是输出而不是代码，所以不需要索引，也不需要任何配置——智能体没有提到文件时，它什么也不显示。

## 🔎 搜索回看缓冲

`⌘F` 或 `Ctrl+Shift+F` 会在终端上方打开查找栏。边输入边跳到第一个匹配项；Enter 和 `⇧Enter` 遍历其余匹配项，计数显示为 `3 / 17`，按 Escape 关闭查找栏并把键盘交还给智能体。匹配项会在网格中高亮，并沿滚动条标记，所以远在上方的匹配项也找得到。

智能体会打印成百上千行，而有意思的错误总是已经滚走的那一条。

## 📋 粘贴大段内容

把 2,000 行的日志或一份很长的差异粘贴到会话中，它会以 2,000 行按键的形式到达，交由智能体自己的编辑器重新排版——这也是智能体 CLI 会把大段粘贴折叠成一个事后无法打开的占位符的原因。Muster 则会把它写入一个文件并输入其路径，这样智能体用文件工具读取它，而且之后它仍然在那里。少于 5,000 个字符的内容照旧原样粘贴。

这些文件与会话记录放在一起，并随会话记录一起过期——不放在系统临时目录里，因为操作系统可能在智能体读取该路径之前就把它清掉；也不放在你的仓库里，否则它们会显示为并非智能体所做的变更。

## ⚠️ 两个标签页改动同一个文件时

在同一个仓库上运行两个智能体——两个 worktree、两个分支——你第一次得知它们在编辑同一个文件，通常是在合并冲突时，那时两者都已经产生了无法同时应用的差异。Muster 拥有每一个标签页，所以它能看到这正在发生：状态栏会标明是哪个文件，以及另外哪个标签页也在改它。

_同一_ 目录中的标签页不受影响。它们是同一个工作区，按定义就共享每一个文件，而一个永远亮着的警告是没人会看的。

## 📼 先前的会话

终端的回看缓冲随窗口一起消失，而智能体 CLI 把它们的对话藏在各自的选择器后面——所以“我昨天在这个文件夹里干了什么”意味着得离开标签页去找。Muster 会在每个会话运行时将其记录下来，所以状态栏中的 **先前的会话** 按钮会列出此目录中发生过的事：哪个智能体、它最后一次输出是多久以前、它输出了多少内容。每次运行一行，包括你当前所在标签页的运行。

如果智能体为对话发布了 ID，该行会提供 **在此标签页中继续**——它会结束那里正在运行的任何东西，并使用智能体自己的恢复参数就地重新打开那段对话。Claude Code 会发布 ID；其他智能体不会，它们的行会如实说明，而不是提供一个会悄悄开始新会话的按钮。

只要有目录，这个按钮就在：会话运行时有，已恢复或刚结束的标签页在下一个会话开始之前也有。

有会话的标签页，侧栏顶部还会有 **在此开始新会话**，它会结束仍在运行的任何东西，把标签页交还给起始界面，目录和智能体仍已填好——这是列表所提问题的另一半。尚未启动任何东西的标签页本来就停在那个界面上，所以那里不会提供它。

记录是逐字的，所以它包含智能体打印过的一切——包括显示在屏幕上的任何机密信息，而且任何以你的身份运行的程序都能读取它们。记录是一项设置，每个会话上限为 4 MB，保留末尾部分，记录会在你设置的保留期限过后删除。任何内容都不会发送到任何地方，目前也没有任何功能会显示记录的内容——列表是根据每个文件的大小和时间生成的。

## 🪟 窗口，留在你离开的地方

Muster 会记住每个窗口的大小、位置、是否最大化以及其中的标签页，所以重启后打开的是你之前在用的那些窗口，而不是一个默认窗口。

把标签页拖出标签栏，在另一个窗口的标签栏以外的任何地方松开，它就会获得一个自己的窗口——在它自己的窗口上方松开也一样，就像 Chrome 那样——在另一个窗口的标签栏上松开则会移到那里；右键点击标签页并选择 **移到新窗口**，无需拖动也能达到同样效果。一个标签会跟随指针显示标签页将去往何处，它将加入的窗口会在其标签栏中标出位置。拖动窗口中唯一的标签页会移动整个窗口。在 Wayland 上，由于它不告诉应用光标或其窗口在哪里，被拖动的标签页仍可以获得自己的窗口，但没有提示标签，单独的标签页不会带着它的窗口移动，标签页也无法放到另一个窗口的标签栏上。正在运行的智能体或 shell 会连同屏幕上的一切一起移动，并继续运行——不会重启任何东西。关闭窗口中的最后一个标签页会关闭该窗口，就像 Chrome 那样；关闭最后一个窗口则退出应用。若该窗口中仍有会话在运行，两者都会先征求确认。在其他窗口仍打开时关闭的窗口，会带走它的标签页。

启动它第二次会聚焦你已有的窗口，而不是打开第二个副本——这很重要，因为两个副本会恢复相同的标签页，为所有标签页各自启动会话，并相互覆盖记录。而在应用已打开的情况下，从 shell 运行 `muster ~/some/project` 会打开一个准备在该目录中启动的标签页。它只是准备好而不是直接启动：要一个文件夹并不等于要一个在其中运行的智能体。

## 🐚 只要一个 shell

起始界面列出智能体；在那个列表下方、模式按钮上方，是 **改为打开普通 shell**，因为 shell 不是其中之一——没有参数，没有模式，没有什么可恢复的。在 macOS 上最小化窗口后，点击程序坞图标即可让它回来；关闭最后一个窗口则会退出应用。

**zsh 或 bash** 标签页会获得两样智能体标签页用不上的东西。输入两个字符后，以相同方式开头的历史命令会出现在光标下方，最新的在前——最上面那条还会以灰色绘制在光标之后。`→` 采用那一条，`↓` 在列表中向下移动，`↑` 往回移动，Enter 把选中的那行填入但不运行，Escape 收起列表。在未动过的提示符处按 `↑` 仍是 shell 自己的历史，带修饰键的按键——`⌥→` 按单词移动、`⇧Enter` 换行——总会到达 shell，所以你已有的操作习惯都不会改变。建议先来自此会话已运行过的命令，最新的在前，然后来自 shell 自己的历史文件——shell 会把这个文件的位置告诉应用，所以你移动过的 `HISTFILE` 正是被读取的那个。一分钟前运行过的命令会排在文件中任何内容之前，而在文件里，它要等 shell 退出后才会出现。

将鼠标悬停在已完成的命令上，其第一行右侧会出现 **复制输出**：点一下就会把它打印的全部内容放到剪贴板，无需选择任何内容。`⌘⇧O`（`Ctrl+Shift+O`）对最后完成的那条命令做同样的事。

这两项都需要应用知道一条命令在哪里结束、下一条从哪里开始，这正是“设置”中的 **Shell 集成** 所开启的：它会让下一个 shell 标签页——以及智能体退出后智能体标签页交给你的那个 shell——使用 Muster 自己的启动文件启动，由它报告这些位置。只有 zsh 和 bash 有这样的文件，而且只在宿主机上，所以 PowerShell、fish 或 WSL 标签页什么也不报告，这两样功能都没有。你自己的配置不会有任何改变——该文件会先加载你的配置，然后再加上这些标记。

## 🚫 文件夹无法读取时

在应用无权列出内容的文件夹中启动会话时，它会直接告诉你，而不是让 shell 失败，`brew`、`mise` 和智能体各自抱怨某个目录“不存在”。它会发出警告，然后让开：再次点击同一个按钮，会话无论如何都会在那里启动，因为无法列出内容的文件夹并不总是无法在其中工作的文件夹。

在 macOS 上，最常见的原因是：`~/Documents`、`~/Desktop` 和 `~/Downloads` 需要你的许可，而且 **你的回答会被记住**——所以如果你点了“不允许”关掉提示，再试一次也无法让它重新出现。Muster 会说明这一点，并提供一个直达隐私设置的按钮，你可以在那里重新开启。由于该应用没有使用 Developer ID 签名，macOS 会把每个新版本当作不同的软件，所以更新后它会再次询问。

在 Windows 上，文件夹会因其自身的权限被拒绝，或者如果它位于“文档”“桌面”或“图片”下，则可能是被“受控文件夹访问”拒绝。在 Linux 上则是文件权限，或者 Flatpak 或 Snap 沙盒。

## 🔔 通知

当智能体完成一轮并交还控制权时，就是你会收到通知的时刻：

- 标签页上的圆点会亮起并闪烁，并且
- 一条桌面通知会写明智能体和标签页，如果智能体发布了它的结束语，还会引用这段话。

智能体以两种不同的方式宣告这一时刻——有些会响起终端铃声，另一些则广播一个结构化事件——两者都会被读取。铃声不需要任何设置。Claude Code 会话使用的结构化事件来自你安装到该 CLI 中的一个 hook 插件，所以没有该插件的会话仍会显示实心的“等待”圆点和状态栏，但没有闪烁，也没有通知。以 API 错误——速率限制、过载——结束的一轮，会和正常完成的一轮以同样的方式宣告。

当你已经在看那个标签页时，什么都不会触发；以两种方式宣告的一轮只会产生一条通知。在 macOS、Linux 和 WSL 上，退出的智能体会把它的标签页交给你的 shell 而不是结束它，并通过一条单独的通知说明这一点，失败时还会附上退出码。结束的会话也会以同样方式宣告——无论是标签页被交给的那个 shell，还是 Windows PowerShell 下的智能体本身。所有这些都可以调整，包括关闭。

## ⚙️ 设置

按下设置快捷键，或点击状态栏右侧的齿轮。“设置”以标签页形式打开，改动会立即生效——包括在已经运行的终端中。有三项是在会话启动时读取的，所以它们作用于下一个会话，而不是已经在运行的会话：**记录会话的输出**、**Shell 集成** 和 **默认终端模式**——对于后者，要更改已打开的标签页，请使用状态栏的“点击 / 回看缓冲”控件。

- **语言**——English（美式或英式）、繁體中文、简体中文或日本語。默认的 _跟随系统_ 会采用你的操作系统首选语言中 Muster 支持的第一种，否则使用美式英语。切换语言绝不会重启会话。
- **新标签页**——启动时使用哪个智能体和目录，以及标签页打开时的 **终端模式**：_点击_，把鼠标交给 Claude Code 自己的提示、子智能体和 shell，并从其对话记录读取圆点；或 _回看缓冲_，保留终端自己的历史，让查找栏和宽度修复有东西可用。一个会话无法两者兼得。状态栏的控件可以切换单个标签页，而不改变这项设置。
- **终端**——主题、字体、字号、行高、字符宽度、回看缓冲、光标闪烁，以及 **Shell 集成**，后者为 zsh 或 bash 标签页提供复制控件和补全。连字已开启：会把 `->`、`=>` 或 `!==` 绘制为单个字形的字体，在这里也会这样显示。字体列表包含机器上安装的所有字体，并筛选出能对齐成列的那些；**显示所有系统字体** 会把其余的也加进来。审阅面板中的差异和文件使用相同的字体绘制，所以一列代码读起来与旁边的输出完全一样。
- **背景**——终端后方的图片，带亮度滑块和一个在图片上显示示例输出的预览，因为亮度只能对照它背后衬着的文字来判断。
- **编辑器**——状态栏按钮打开哪个编辑器。
- **通知**——是否通知，在你正看着的标签页上是否保持安静，是否播放声音。
- **Git**——多久重新读取一次状态，历史记录加载多少个提交。
- **会话记录**——是否记录会话的输出，以及这些记录保留多久。
- **数据**——清除记住的目录，或恢复所有默认值。

在安装了 WSL 的 Windows 上，**新标签页** 还可以在 Windows 和某个发行版之间选择。

## 🩹 如果出现异常

**拖入的文件没有输入任何内容。** 包含控制字符的路径会被拒绝而不是输入，因为结束括号粘贴模式的序列可能是文件名的一部分——那样的话，文件名的其余部分就会以按键的形式到达。如果你确实要用这个文件，请给它改名。

**出现关于你从没听说过的 tap 的警告。** Homebrew 6 在第三方 tap 被信任之前拒绝加载它们，并且会在 _每一条_ 命令上列出你机器上的 _每一个_ 未受信任的 tap——所以一个与 Muster 无关的 tap 可能会塞满安装输出的中间部分。这只是噪音，并非失败；请看末尾的 `successfully installed`。Muster 自己不需要 `brew trust`：明确指定 cask 的名字就是对它的授权。

**`brew tap ronny1020/tap` 失败，报 `Cannot tap ronny1020/tap: invalid syntax in tap!`。** 你不需要 tap 任何东西——安装命令会替你完成。单独执行 tap 会撞上 Homebrew 的信任规则：它在 tap 时就会校验 cask，并拒绝从你没有信任的 tap 加载 cask。按名字请求这个 cask，就是授予信任的方式。

**刚安装完，双击它却毫无反应。** macOS 需要一点时间来登记一个刚被替换的应用包。再打开一次它就会启动。

**`brew install` 提示 `Warning: Not upgrading muster, the latest version is already installed`，而应用确实在。** 这是 Homebrew 在告诉你它已经安装了，并不是错误——无需做任何事。如果仍想强制装一份全新的副本，请使用 `brew reinstall --cask ronny1020/tap/muster`。

**`brew install` 提示“already installed”，但应用并不存在。** 应用是被手动删除的，所以 Homebrew 的记录与磁盘不一致，`brew install` 会一直报告成功却什么也不装。用 `brew reinstall --cask ronny1020/tap/muster` 修复，然后照上文清除隔离属性。

**会话启动时出现“command not found”。** 该智能体的 CLI 没有安装，或者不在你的登录 shell 设置的 `PATH` 中。请确认上表中的命令能在你自己的终端里运行。

**没有桌面通知。** 在操作系统询问时授予应用通知权限，或之后在系统设置中授予。如果某个 Claude Code 标签页的圆点变成实心却一直没有通知，说明该 CLI 没有安装通知插件——圆点是从会话自身的输出中读出来的，什么都不需要；通知则需要插件。在 Claude Code 会话中用 `/plugin marketplace add warpdotdev/claude-code-warp` 安装一个，然后运行 `/plugin install warp@claude-code-warp`，再运行 `/reload-plugins`——在重新加载之前它什么也不做。它还需要 `PATH` 上有 `jq`（`brew install jq`，或你系统的包管理器），因为它的每个 hook 都要通过它处理数据。**WSL** 标签页不会收到通知，除非你 Windows 上的 `WSLENV` 列出了 `WARP_CLI_AGENT_PROTOCOL_VERSION` 和 `WARP_CLIENT_VERSION`——它仍会宣告智能体退出、会话结束以及智能体响铃，但不会宣告一轮的结束。

**智能体标签页直接掉到 shell 提示符**（在 Windows PowerShell 标签页中：立即显示“已退出 1”）。是智能体本身拒绝启动——参数错误、CLI 没有安装——它自己在提示符上方的输出会说明原因。修正之后在那个 shell 里再运行一次命令，或者使用标签页的 **返回开始页面** 按钮——你输入 `exit` 后它就会出现，在 PowerShell 下则会立即出现。

## 🔒 你的数据

设置、记住的目录以及你拖动面板得到的宽度都由应用保存；目前还没有可以编辑的配置文件。另外还有三样东西保存在磁盘上，都会在“设置 → 会话记录”中的保留期限过后过期：每个会话所输出内容的逐字记录、每份记录旁一个写明智能体和对话的小文件，以及每次超大粘贴的副本。记录 **默认开启**，开关也在同一个地方；粘贴副本没有开关——只要粘贴的内容大到需要变成文件，就会写入。记录包含什么，请参见上文“先前的会话”。审阅面板和文件栏读取的一切都在你自己的磁盘上。文件的 _内容_ 在你打开它时读取；审阅面板还会读取新文件——git 还没见过的那些——以统计它们会增加多少行，最多读取前几百个。这只发生在“变更”视图中，因为显示这些数字的就是它：在文件树上打开侧栏只会询问 git 哪些文件有差异，不会读取其中任何一个。在终端中点击路径也会向 git 问同样的问题，然后，只有当那个文件是 Muster 会亲自展示给你的文件时才读取它：一张图片，它会变成你要看的那张图；或者一个解析后位于会话自身目录下某处的文件，它会在终端旁的那一栏中打开。最后这项检查是把解析后的路径与该目录作比较，目前用的是前缀匹配——智能体写出的带有 `../` 的路径仍可能满足它，所以请把它理解为“智能体所说的位置”，而不是一道边界。

有一样东西会经由 Muster 本身离开你的机器：鼠标指针停在网页链接上时，会为悬停预览获取该页面的标题和图片（参见上文“隐私”）。你打开的网址——无论在终端中还是在渲染后的文档中——都会交给你的浏览器，而你运行的智能体，是你自己选的那些。
